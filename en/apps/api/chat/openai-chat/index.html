Chat Completions

Call chat models with message lists for text, multimodal input, function calls, and SSE streaming.

Endpoint overview

POST /v1/chat/completions generates assistant replies from message history. It suits existing Chat Completions clients and stateless multi-turn conversations.

The gateway URL is https://api.dwchainless.com, with the request header Authorization: Bearer $SIMIROUTER_API_KEY. Direct OpenAI access uses https://api.openai.com and Bearer authentication, but requires an OpenAI key. Select a model available to the account that supports the required capability.

Quick start

  1. Prepare configuration: create a key in API key management and copy a full model ID that supports Chat Completions from Models and pricing.
  2. Send a minimal request: submit a single user message and keep stream set to false; first confirm that authentication, the model, and parameters are valid.
  3. Read the result: the request succeeds only when HTTP is 2xx and choices[] is non-empty; the text is in choices[0].message.content.
  4. Verify: check finish_reason, refusals, and the actual content, then confirm against the usage logs.

Replace PASTE_API_KEY_HERE and MODEL_ID with real values; once it works, add multi-turn history or tools, or enable streaming.

If the project already uses the OpenAI SDK, point baseURL at https://api.dwchainless.com/v1 and swap in a SimiRouter key; method names and parameters stay unchanged. See API request scripts.

Request parameters

The content type is application/json. Omit unused optional fields; do not send empty strings, zeroes, empty objects, or null values indiscriminately.

max_tokens is a legacy parameter replaced by max_completion_tokens; non-o-series models may still accept it, while /v1/completions still uses only max_tokens. New integrations should not send both. video_url, reasoning_content are extensions in some compatible models, not universal OpenAI Chat Completions fields.

Streaming responses

Set stream: true then receive text/event-stream. Parse JSON from each data: line; use choices[].index to group and concatenate delta.content; group function arguments from delta.tool_calls by tool index. The completion marker is data: [DONE], not a JSON object. With include_usage, the final usage chunk may have empty choices, and ordinary chunks may have usage=null. If the connection closes without an end signal, mark the reply incomplete rather than automatically successful.

Code examples

Set SIMIROUTER_API_KEY, SIMIROUTER_MODEL; SIMIROUTER_BASE_URL overrides the default gateway root; do not append /v1. Python 3, Node.js 18+, and Go examples use only standard libraries. The curl example uses Python 3 to encode JSON safely.

Using the OpenAI SDK

With the official openai SDK installed you do not need to hand-write HTTP requests: point baseURL at the gateway to reuse the official types, retries and stream parsing. Install it with pip install openai or npm install openai.

Errors

HTTP statusMeaning or vendor error typeAction
400Invalid requestCheck required fields, JSON, model parameters, and context length.
401Authentication failedCheck that the key exists, is valid, and belongs to the correct service.
403 / 404Access denied / resource not foundCheck model permissions, resource IDs, and the URL.
429Rate or quota limitDistinguish rate limits from insufficient quota using the response body; retrying cannot fix insufficient quota.
500 / 503Server error / temporarily unavailableRetain the request identifier and use bounded backoff for transient failures.

Native OpenAI errors usually contain error.message, error.type, error.param, error.code; param, code may be null; do not assume these fields always exist or equal the HTTP status. The gateway may return authentication, routing, or quota errors before contacting the vendor; the status alone does not establish an upstream error. Under HTTP 200, still inspect finish_reason, refusals, and stream completeness; length and content_filter are not HTTP errors.

Long replies and streaming requests can take from tens of seconds to several minutes; set a sufficient client timeout, and when the stream breaks, judge from the deltas received and the termination reason instead of resending automatically. For 429 and 5xx, inspect the response body and usage logs first; when content policy rejects a request, change the prompt or input rather than retrying unchanged.

FAQ

What should I do about a 401 or Invalid token? Check that the header is Authorization: Bearer <Key>, that the key belongs to this gateway and has not been revoked, and that you did not paste your login password or a provider key.

Why do I get 404 or a missing-model error? model must be a full model ID from Models & pricing, and your key's group must be allowed to use it. SDK users should also confirm that baseURL includes /v1.

Should I retry a 429? Read the response body first. For rate limiting, retry with exponential backoff and jitter; for exhausted quota or balance, retrying cannot succeed — top up or adjust the limit instead.

When is a streamed response complete? Only after data: [DONE] and a final chunk carrying finish_reason. If the connection drops without an end marker, treat the reply as incomplete and do not automatically resend a request you have already paid for.

max_tokens or max_completion_tokens? Use max_completion_tokens for Chat Completions. max_tokens is the legacy field and only some models still accept it. Never send both; /v1/completions still uses only max_tokens.

Why does temperature have no effect? Some reasoning models fix sampling or accept only default values, and the gateway passes values through to the provider. Follow that model's documentation and errors instead of assuming every OpenAI parameter applies.
