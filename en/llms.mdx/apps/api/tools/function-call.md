# Function tool calling

## Endpoint overview

`POST /v1/chat/completions` uses tools to tell the model which functions are available. The model generates only function names and arguments. The application validates, authorizes, and executes them, then returns results in tool messages and requests a final answer. Function calling itself does not access databases, transfer funds, or send notifications for the application.

The gateway URL is `https://api.dwchainless.com`, with the request header `Authorization: Bearer $SIMIROUTER_API_KEY`. Direct OpenAI access uses `https://api.openai.com` and Bearer authentication, but requires an OpenAI key. Select a model available to the account that supports the required capability.

## Request parameters

| Field                         | Type            | Required    | Description                                                                                                                |
| ----------------------------- | --------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| model / messages              | string / array  | Yes         | Model and conversation; the model must support function tools.                                                             |
| tools\[].type                 | string          | Yes         | function here.                                                                                                             |
| tools\[].function.name        | string          | Yes         | The function name, dispatched through an application allowlist.                                                            |
| tools\[].function.description | string          | No          | Describe its purpose, input boundaries, and side effects.                                                                  |
| tools\[].function.parameters  | object          | Yes         | JSON Schema for function arguments.                                                                                        |
| tools\[].function.strict      | boolean         | No          | true requires strict adherence to the supported Schema subset.                                                             |
| tool\_choice                  | string / object | No          | auto lets the model choose; none disables tools; required requires at least one; a specific function can also be selected. |
| parallel\_tool\_calls         | boolean         | No          | Allow multiple calls in one turn; false limits it to at most one.                                                          |
| messages\[].tool\_call\_id    | string          | Conditional | When returning a tool message, match the assistant tool\_calls id.                                                         |
| messages\[].content           | string          | Conditional | The execution result in the tool message; JSON-serialized text is recommended.                                             |

With strict=true, each object requires additionalProperties=false and all properties in required. Logically optional fields can permit null. Unsupported Schemas cause request errors.

### First request

```json
{
  "model": "MODEL_ID",
  "messages": [
    {
      "role": "user",
      "content": "请计算17乘以23。"
    }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "multiply_numbers",
        "description": "将两个整数相乘。",
        "strict": true,
        "parameters": {
          "type": "object",
          "properties": {
            "a": {
              "type": "integer"
            },
            "b": {
              "type": "integer"
            }
          },
          "required": [
            "a",
            "b"
          ],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": "auto",
  "parallel_tool_calls": false,
  "stream": false
}
```

## Response

| Field                                | Type          | Description                                                                                    |
| ------------------------------------ | ------------- | ---------------------------------------------------------------------------------------------- |
| choices\[].message.tool\_calls\[].id | string        | The tool-call ID used as tool\_call\_id afterward.                                             |
| tool\_calls\[].type                  | string        | function.                                                                                      |
| tool\_calls\[].function.name         | string        | The requested function name; must match the application allowlist.                             |
| tool\_calls\[].function.arguments    | string        | JSON text, not a parsed object; parse, then validate types and values.                         |
| choices\[].message.content           | string / null | May be null during function calling.                                                           |
| choices\[].finish\_reason            | string        | tool\_calls means tools need execution; stop usually indicates a final natural-language reply. |
| usage                                | object        | Each model request incurs its own token usage.                                                 |

```json
{
  "id": "chatcmpl_tool_example",
  "object": "chat.completion",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_example",
            "type": "function",
            "function": {
              "name": "multiply_numbers",
              "arguments": "{\"a\":17,\"b\":23}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ]
}
```

### Execute and return results

Validate name=multiply\_numbers and that a and b are integers in the allowed range; the result is 391. The following is the complete second request. Replace call\_example with the actual ID from the first response; a static ID cannot be reused for arbitrary requests.

```json
{
  "model": "MODEL_ID",
  "messages": [
    {
      "role": "user",
      "content": "请计算17乘以23。"
    },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_example",
          "type": "function",
          "function": {
            "name": "multiply_numbers",
            "arguments": "{\"a\":17,\"b\":23}"
          }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "call_example",
      "content": "391"
    }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "multiply_numbers",
        "description": "将两个整数相乘。",
        "strict": true,
        "parameters": {
          "type": "object",
          "properties": {
            "a": {
              "type": "integer"
            },
            "b": {
              "type": "integer"
            }
          },
          "required": [
            "a",
            "b"
          ],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": "none",
  "stream": false
}
```

Return a result for every tool\_call; do not omit results or mix IDs from other conversations. Execute concurrently only authorized, independent tools. Sending, charging, and similar side effects need separate idempotency controls; a repeated model request must not cause duplicate execution.

### Responses format differences

Responses defines type, name, description, parameters, and strict directly in tools\[], without a function wrapper. It returns type=function\_call output items; return results using `{"type":"function_call_output","call_id":"...","output":"391"}`. Do not mix Chat tool\_call\_id with Responses call\_id.

## Code examples

The four language examples automatically execute one side-effect-free local multiplication and return it, with at most two model requests and no infinite loop. Set `SIMIROUTER_API_KEY`, `SIMIROUTER_MODEL`; `SIMIROUTER_BASE_URL` overrides the default gateway root; do not append `/v1`. Python 3, Node.js 18+, and Go examples use only standard libraries. The curl example uses Python 3 to encode JSON safely.

    try:
        with urllib.request.urlopen(request, timeout=120) as response:
            result = json.load(response)

        print(f"HTTP {error.code}: {error.read().decode()}", file=sys.stderr)
        raise SystemExit(1)
    assistant = result["choices"][0]["message"]
    body["messages"].append(assistant)
    for call in assistant.get("tool_calls", []):
        if call.get("type") != "function" or call["function"]["name"] != "multiply_numbers":
            raise ValueError("未知函数")
        args = json.loads(call["function"]["arguments"])
        if set(args) != {"a", "b"} or any(type(args[k]) is not int or abs(args[k]) > 1000000 for k in ("a", "b")):
            raise ValueError("参数须为绝对值不超过1000000的两个整数")
        body["messages"].append({"role": "tool", "tool_call_id": call["id"], "content": str(args["a"] * args["b"])})
    if assistant.get("tool_calls"):
        body["tool_choice"] = "none"
        request.data = json.dumps(body).encode("utf-8")
        try:
            with urllib.request.urlopen(request, timeout=120) as response:
                result = json.load(response)
        except urllib.error.HTTPError as error:
            print(f"HTTP {error.code}: {error.read().decode()}", file=sys.stderr)
            raise SystemExit(1)
    print(json.dumps(result, ensure_ascii=False, indent=2))

## Errors

| HTTP status | Meaning or vendor error type           | Action                                                                                                           |
| ----------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 400         | Invalid request                        | Check required fields, JSON, model parameters, and context length.                                               |
| 401         | Authentication failed                  | Check that the key exists, is valid, and belongs to the correct service.                                         |
| 403 / 404   | Access denied / resource not found     | Check model permissions, resource IDs, and the URL.                                                              |
| 429         | Rate or quota limit                    | Distinguish rate limits from insufficient quota using the response body; retrying cannot fix insufficient quota. |
| 500 / 503   | Server error / temporarily unavailable | Retain the request identifier and use bounded backoff for transient failures.                                    |

Native OpenAI errors usually contain `error.message`, `error.type`, `error.param`, `error.code`; `param`, `code` may be `null`; do not assume these fields always exist or equal the HTTP status. The gateway may return authentication, routing, or quota errors before contacting the vendor; the status alone does not establish an upstream error. Invalid arguments JSON, unknown functions, or execution failures are application errors; never fabricate tool success. A successful HTTP response may only request a tool rather than complete the user’s task.
