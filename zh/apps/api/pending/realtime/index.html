OpenAI Realtime API

独立的 WebRTC/WebSocket 实时语音会话参考。

接口说明

Realtime 提供有状态、低延迟的语音与文字交互，客户端持续发送事件，服务端持续输出音频、文字和工具调用事件。它独立于 TTS、文件转录 和 文件翻译。

场景官方接入鉴权
服务端 WebSocketwss://api.openai.com/v1/realtime?model=gpt-realtime-2.1OpenAI API Key Bearer
浏览器 WebRTC/v1/realtime/calls，先在服务器创建临时凭证短期 client secret，不能暴露标准 Key
持续转录Realtime transcription 专用会话配置使用对应 intent/config，不等同于普通对话

本页示例直连 OpenAI；SimiRouter 是否提供 WebSocket 升级、事件透传和模型权限需确认专用渠道。不能把普通 HTTP GET 结果当作实时连接成功。GA 协议不使用旧 OpenAI-Beta: realtime=v1。

请求参数

字段类型必填说明
model（连接query）string条件创建会话的模型，例 gpt-realtime-2.1；加入既有 call 时使用 call_id。
call_id（连接query）string条件加入已建立通话，不能与创建新会话模型混淆。
session.typestring是会话更新使用 realtime，转录使用独立配置。
session.instructionsstring否系统级风格与行为指令。
session.output_modalitiesstring[]否text 或 audio，按当前 Realtime 会话配置。
session.audioobject否输入/输出音频格式、声音与语音检测配置；必须匹配采集/播放编码。
session.tools / tool_choicearray / string否工具定义与选择；工具参数需在业务端校验。
event_idstring否客户端追踪 ID，便于对应错误事件。

常用客户端事件

事件用途
session.update更新会话配置，等待 session.updated 读取实际配置。
conversation.item.create向会话添加文字或其他允许的内容项。
input_audio_buffer.append音频 Base64 块，编码必须与 session.audio.input.format 一致。
input_audio_buffer.commit提交缓冲；只提交不等于自动创建回复。
input_audio_buffer.clear丢弃未提交的输入。
response.create请求生成回复。
response.cancel取消正在生成的回复；播放端还需处理已缓冲音频。

持续麦克风应按真实采样率分块送入，VAD 决定何时自动提交/生成。打断时还需按官方协议清理播放缓冲或截断会话项，不能只停止扬声器。

返回值

服务端事件关键字段/意义
session.created / session.updated会话标识与实际配置。
response.output_text.deltadelta 文本增量。
response.output_audio.deltadelta 是 Base64 音频增量，需解码。
response.output_audio_transcript.delta语音对应文字，不代替音频本身。
response.doneresponse.status 与 usage；只有 completed 才是正常完成。
errorerror.type、code、message、event_id 等。

Realtime 是双向 WebSocket 事件，不是 data: SSE。断开连接或得到部分音频不能当作完整成功，也不能由文字长度推算最终计费。

代码调用

设置官方 OPENAI_API_KEY。Python 需 python3 -m pip install websockets；Node.js 需 npm install ws；Go 需 go get github.com/gorilla/websocket。以下发送一轮文字以验证完整事件流程，不是麦克风/扬声器集成，最多等待 60 秒。

错误码

握手阶段按 HTTP 400/401/403/404/429 判断参数、认证、权限、模型和配额。连接建立后必须处理 error 事件、response.done 中的失败状态与 WebSocket close code/reason。异常断连或超时需报告未完成；应用重连后重新建立状态，不能盲目重放已触发的工具或有副作用操作。
