图片生成

通过 Images API 从文字提示生成图片，并读取返回的 Base64 结果。

接口说明

POST /v1/images/generations 根据 prompt 生成一张或多张图片。

接入地址为 https://api.dwchainless.com，请求头使用 Authorization: Bearer $API_KEY。OpenAI 官方直连为 https://api.openai.com，同样使用 Bearer 鉴权，但必须换成 OpenAI 的 Key。 模型名称应选用账户可访问且支持目标能力的模型。

本页使用 GPT Image 参数。不同厂商的 OpenAI 兼容图片模型可能接受不同尺寸、质量与返回格式，不能把这些差异当成同一官方标准。

快速开始

  1. 准备配置：在 API 密钥管理 创建密钥，从模型与价格复制支持 Images API 的模型 ID。
  2. 发送请求：向 https://api.dwchainless.com/v1/images/generations 发送 JSON，请求头使用 Authorization: Bearer $API_KEY，请求体至少包含 model 和 prompt。
  3. 读取结果：HTTP 2xx 且 data[] 非空才算成功；GPT Image 从 data[].b64_json 解码保存。
  4. 确认完成：检查文件能否打开、尺寸是否符合要求，再核对使用日志。

最小请求如下；确认可用后，再调整数量、尺寸或开启流式：

请求参数

请求体为 JSON。

字段类型必填说明
modelstring是支持 Images API 的图像模型 ID。
promptstring是具体描述主体、构图、风格及文字内容。
ninteger否生成数量，OpenAI GPT Image 原生范围为 1–10，示例为 1。
sizestring否OpenAI 原生写法为 WIDTHxHEIGHT（宽高均为 16 的倍数，比例需在 1:3–3:1 之间）或 auto；SimiRouter 另接受比例与 resolution 组合，可用值和上限随模型变化。
resolutionstring否SimiRouter 扩展字段：与比例配合的档位 1k、2k 或 4k，不是像素值；OpenAI 原生接口没有该字段。
aspect_ratiostring否SimiRouter 扩展字段：单独的比例，如 3:4；size 已写比例时以 size 为准。
qualitystring否auto、low、medium、high；部分新模型另支持 xhigh、max。
output_formatstring否png、jpeg（示例）、webp；官方规范还列出 gif、svg，需模型与项目权限支持。
output_compressioninteger否JPEG/WebP 压缩质量 0–100，不用于 PNG。
backgroundstring否auto、opaque、transparent；透明背景需支持的模型与 PNG/WebP。
moderationstring否auto 或支持的 low；不保证请求一定通过内容策略。
response_formatstring否部分兼容模型支持 url 或 b64_json；GPT Image 原生不使用。
streamboolean否true 使用图像 SSE 事件。
partial_imagesinteger否stream=true 时请求 0–3 个中间图像，仍需等最终完成事件。

GPT Image 的图片直接以 Base64 返回，不应依赖旧式 response_format=url/b64_json。部分兼容模型可用该字段选择 URL 或 Base64，是否生效以模型说明和实际返回为准。旧 style=vivid/natural 也不适用于 GPT Image，风格应写进 prompt。

尺寸与格式

K 是分辨率的常用简称，不是文件大小，也不表示质量参数。实际宽高随模型与比例变化；同一比例下边长翻倍，总像素为四倍。以下仅作科普，不能直接当作所有模型的可用尺寸。

OpenAI 使用 size 填写模型允许的宽高，如 1024x1024，不是直接填写 1K；quality、output_format 与尺寸分别控制质量和格式。

分辨率称呼常见像素示意（不是模型支持承诺）
1K两边均 ≤ 1024 像素；如 1024×1024。
2K最长边 > 1024 且 ≤ 2048 像素；如 1280×720。
4K任一边 > 2048 像素；如 2560×1440。

本站按张计费档位是另一套规则，不能把上面的科普示意直接套为收费标准。 图片规格与计费规则。

尺寸的三种写法

部分 OpenAI 兼容网关除明确像素外，还接受比例加分辨率或自动尺寸；字段是否生效取决于模型与渠道，不被支持时应退回明确像素。

写法请求片段说明
明确像素（推荐）{"size":"1536x2048"}最直观，避免预设换算差异。
比例 + 分辨率{"size":"3:4","resolution":"2k"}使用 2K、3:4 预设；resolution 只接受 1k、2k、4k。
自动尺寸{"size":"auto"}由模型选择宽高，不承诺固定像素。
  • 比例写进 size 时优先于单独的 aspect_ratio；明确像素或 auto 优先于比例预设。
  • 档位写在 resolution，不要发送 size=2k；尺寸分隔符使用小写英文 x。
  • OpenAI 官方对 gpt-image-2 的任意尺寸上限为 3840×2160；4096×4096 等更大组合通常返回参数错误。上表 4K 只是档位示意，不代表该像素组合一定可用。
  • 14 种常用比例的 1K、2K、4K 速查见图片规格与计费规则。

返回值

字段类型说明
createdinteger创建时间，Unix 秒。
data[]array生成结果列表，不可假定一定有第一项。
data[].b64_jsonstring图片二进制的 Base64；GPT Image 使用此格式。
data[].urlstring只在支持 URL 输出的兼容模型中出现，不能视为 GPT Image 必有字段。
data[].revised_promptstring部分旧或兼容模型返回的改写提示，不是 GPT Image 必有字段。
output_format / size / quality / backgroundstring可选有效输出配置。
usageobject可选用量数据，出现与计量粒度随模型和服务变化。
usage.input_tokens / output_tokens / total_tokensinteger如返回则为输入、输出、总 Token。
usage.input_tokens_detailsobject可选 image_tokens、text_tokens 等细分。
X-Request-Idstring响应头，不是 JSON 字段；反馈或排查问题时保留。

返回的 data[].url 可能有有效期，下载图片时不要附带 API Key。以下 Base64 仅为最小 PNG 的结构示例，不是上面提示的真实生成结果。

流式生成

支持的模型可设置 stream=true，以 image_generation.partial_image 接收中间预览，以 image_generation.completed 接收最终图片和用量。部分图像不是最终结果；断流且没有 completed 时不要将预览标记为已完成。生成接口不返回可轮询的通用后台任务 ID。

代码调用

在代码顶部填写 API_URL、API_KEY，示例使用 gpt-image-2。API_URL 是完整请求地址，默认使用网关 https://api.dwchainless.com。示例只用标准库，发送一次请求并把返回 JSON 打印到标准输出，不自动保存图片。

错误码

HTTP 状态含义或厂商错误类型处理方式
400请求无效检查必填字段、JSON、模型参数和上下文长度。
401认证失败检查 Key 是否存在、有效及归属正确。
403 / 404无权访问 / 资源不存在检查模型权限、资源 ID 和 URL。
413请求体或图片过大优先使用图片 URL；减小 Base64 体积或图片尺寸。
429速率或配额限制结合响应体区分限流与额度不足，后者不能靠重试解决。
500 / 502 / 503服务错误 / 上游繁忙 / 暂时不可用保留请求标识，对暂时故障做有限次数退避。

OpenAI 原生错误通常包含 error.message、error.type、error.param、error.code；param、code 可为 null，不能假定其始终存在或等于 HTTP 状态码。 网关可能在请求到达厂商前返回认证、路由或额度错误；不得仅凭 HTTP 数字判定错误来自上游。 响应 data 为空、缺少图片数据或只有中间预览时，不能仅凭 HTTP 200 宣称生成完成。

生成和编辑可能耗时数十秒到数分钟，客户端应设置足够超时；请求挂起不等于失败。超时、断流或 5xx 后先确认请求是否已经执行，再决定是否重试，避免重复生成和重复扣费。内容策略拒绝（通常为 400）时修改提示词或参考图，不要原样重试。
