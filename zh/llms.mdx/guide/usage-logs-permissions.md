# 使用日志与审计日志权限

这篇说明使用日志和审计日志在不同角色下的可见范围，以及如何排查请求实际经过的渠道。

## 使用日志

### 超级管理员

超级管理员可以查看所有用户的完整日志。打开 [使用日志](https://api.dwchainless.com/usage-logs/common) 后，在“日志类型”筛选中选择“仅看错误”，即可只查看所有用户的错误调用。该筛选会保留重试期间的错误记录，不会因为最终请求成功而隐藏中间错误。

日志中的渠道列表示这次请求实际使用的渠道名称。排查路由时，应以日志中的实际渠道、模型、状态和请求 ID 为准，不要只根据客户端显示的模型名称判断。

### 管理员

管理员只能查看自己的请求、充值、管理操作和错误调用日志，不能通过用户名、角色参数或修改 URL 查看其他用户。管理员没有面向全局的“仅看错误”筛选，但自己的错误记录仍会按权限正常显示在日志中。

### 普通用户

普通用户只能查看自己的请求、充值和管理员操作相关日志，不能查看错误日志或其他用户的日志。

## 审计日志

超级管理员可以查看所有用户的审计事件并按用户名筛选。管理员和普通用户只能查看当前登录账号自己的审计事件；页面参数不会扩大服务端权限范围。

## 渠道状态更新

审计事件 `channel.status_update` 表示一次手动的单渠道状态操作。当前代码记录的目标状态为启用或手动禁用；即使 `changed=false`（请求成功但实际状态未变化），也会记录该事件。批量操作对应 `channel.status_update_batch`。需要确认具体变化时，请查看事件详情、操作人和时间。

## 错误排查建议

1. 先确认时间范围和请求 ID。
2. 超级管理员排查全局异常时选择“仅看错误”。
3. 核对实际渠道、模型和状态，不要仅依据客户端名称。
4. 对超时、5xx 或流式中断，先查看现有日志和请求 ID，再决定是否重试，避免重复扣费。
