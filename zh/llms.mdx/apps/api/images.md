# 画图

先选 **API 协议**，再确定要做的 **效果**，最后核对 **尺寸、质量、格式和张数**。协议决定请求与响应结构，效果由模型能力和提示词共同决定，规格决定输出要求；三者不能混为一谈。

生成和编辑返回图片；图片理解以图片为输入，返回文字或结构化结果。普通文本模型不会因为加入图片参数就获得生图能力。调用前从[模型与价格](https://api.dwchainless.com/zh/pricing/)确认准确模型 ID、接口支持、计费分组和额度，真实请求可能产生费用。

## 概览

| 你要做什么     | 输入             | 输出        | 典型端点                          |
| --------- | -------------- | --------- | ----------------------------- |
| 从文字生成图片   | 提示词            | 新图片       | `POST /v1/images/generations` |
| 修改已有图片    | 提示词 + 一张或多张参考图 | 编辑后的图片    | `POST /v1/images/edits`       |
| 在对话中边聊边生图 | 对话消息 + 图像工具    | 图片与文字混合结果 | `POST /v1/responses`          |
| 让模型看图说话   | 图片 + 问题        | 文字，不是新图片  | `POST /v1/chat/completions`   |

## 核心概念

先分清三类数字，后面的参数和价格才说得通：

* **像素尺寸**：真实的宽 × 高，例如 `1024x1024`。它决定文件的实际分辨率，不是文件大小，也不等于质量档位。
* **宽高比**：`1:1`、`16:9`、`9:16` 这类比例，只决定画幅形状。同一比例可以对应多种像素尺寸；只说比例不等于指定了输出大小。
* **分辨率档位**：`1K`、`2K`、`4K` 这类档位。厂商的原生档位按最长边或产品线定义，本站的按张计费档位则按最长边归档；两者名称相同，边界不一定相同，不能直接互相推断。

还有三个常见误解：`quality` 控制渲染质量，不是压缩质量；PNG、JPEG、WebP 是文件格式，改扩展名不会转换格式；Base64 与 URL 只是交付方式，不是分辨率。逐项对照见下文「四、图片规格与计费」。

| --------- | --------------- | ----------------------------------------------------- | ----------------------------------------- | ------------------------------------------- |

**通义千问这一节使用 Qwen 原生请求体，通过本站网关的 `/v1/images/generations` 与 `/v1/images/edits` 调用，返回统一为 `data[]`。** 不要把正文改写成 OpenAI 的 `prompt` 字段；模型 ID 应使用本站渠道实际提供的名称。即梦使用火山方舟原生请求体；Grok 的路径与 OpenAI Images 相同，但画幅参数换成了 `aspect_ratio` 与 `resolution`；FLUX 没有同步出图，必须先提交任务再轮询 `polling_url`。三者不能互相照搬字段。

## 二、各种效果：按目标选择

“水彩”“换背景”“商品合成”等通常是生成或编辑任务，不是各自独立的 API。以下是任务分类，不是全模型能力承诺；先在对应协议和模型说明中确认支持范围。

| 想要的效果              | 输入与提示词重点              | 接口选择与限制                          |
| ------------------ | --------------------- | -------------------------------- |
| 从零创作：插画、封面、海报、写实画面 | 描述主体、构图、风格、光线与需要呈现的文字 | 选文生图；文字与细节需检查                    |
| 参考图变体：沿用主体或构图重新生成  | 提供参考图，分别说明保留项与改变项     | 选图片编辑 / 以图生图；不能保证逐像素保持           |
| 风格转换：照片转水彩、线稿等     | 参考图加目标风格，说明主体和布局是否保留  | 选支持参考图的编辑模型                      |
| 背景替换、增删元素、局部修改     | 明确修改区域；支持时提供蒙版        | 选编辑接口；蒙版支持和规则随模型变化               |
| 多图组合：商品、人物与场景合成    | 给出各参考图的用途、主体关系和最终布局   | 选支持多图输入的编辑模型，核对图片数量上限            |
| 多轮迭代：基于上一张继续修改     | 保留协议要求的历史内容或引用信息      | 选支持多轮图像工作的接口；不能只保存一段文字就假定图像上下文仍在 |
| 透明背景素材             | 明确需要真实透明通道，而非白底或棋盘格画面 | 仅在模型支持时选择透明背景和可保留透明通道的输出格式       |
| 识图、提取文字、图表问答       | 输入图片并说明分析目标           | 选图片理解接口，返回文字而非编辑后的图              |

这些能力与限制可参考 [OpenAI 图像生成](https\://developers.openai.com/api/docs/guides/image-generation)、[Gemini 图像生成与编辑](https\://ai.google.dev/gemini-api/docs/image-generation)、[Qwen 图像编辑](https\://www.alibabacloud.com/help/en/model-studio/qwen-image-edit-api)。官方示例不代表当前网关渠道已开放相同能力。

## 三、发起调用：四步完成第一张图

无论选择哪套协议，调用都遵循同一顺序：确认配置、选择端点、发送最小请求、读取并验收结果。下面只描述通用流程，具体字段以对应协议页面为准。

### 1. 确认请求地址、密钥与模型

* **请求地址**：本站网关为 `https://api.dwchainless.com`，端点路径随协议和操作变化。
* **密钥**：在 [API 密钥管理](https://api.dwchainless.com/keys) 创建，请求时通过 `Authorization: Bearer $API_KEY` 携带；不要写进提示词、源码、截图或 Git。
* **模型**：从[模型与价格](https://api.dwchainless.com/zh/pricing/)复制完整模型 ID，并确认它支持目标端点。生成、编辑和图片理解可能由不同模型提供。

### 2. 选择端点与请求格式

按上方的协议表选择端点，再确认请求体格式：

| 操作          | 端点（OpenAI 格式）                 | 请求格式                        |
| ----------- | ----------------------------- | --------------------------- |
| 文字生图        | `POST /v1/images/generations` | JSON                        |
| 图片编辑 / 以图生图 | `POST /v1/images/edits`       | JSON `images[]` 或 multipart |
| 对话式生图       | `POST /v1/responses`          | JSON，启用图像工具                 |
| 图片理解        | `POST /v1/chat/completions`   | JSON，内容项含 `image_url`       |

Gemini、通义千问、即梦、Grok 和 FLUX 使用各自的原生请求字段，不能把 OpenAI 字段直接照搬过去。

### 3. 发送最小请求

第一次调用只生成一张、不使用流式，先确认鉴权、模型和参数都有效。以下以 OpenAI 生图为例：

```bash
API_URL="https://api.dwchainless.com/v1/images/generations"
API_KEY="PASTE_API_KEY_HERE"
curl "$API_URL" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "一只小机器人在图书馆阅读，水彩插画，不要文字。",
    "n": 1,
    "size": "1024x1024",
    "output_format": "png"
  }'
```

确认返回正常后，再按需增加 `n`、调整尺寸或开启流式。完整的多语言示例见[生成](/simidoc/zh/apps/api/images/openai/generations)和[编辑](/simidoc/zh/apps/api/images/openai/edits)。

**返回形态（示意）**：真实响应的 Base64 很长，这里只保留开头；成功时看 `data[]` 而不只是 HTTP 200。

```json
{
  "created": 1763366400,
  "data": [{ "b64_json": "iVBORw0KGgoAAAANSUhEUg..." }],
  "usage": { "input_tokens": 28, "output_tokens": 4160, "total_tokens": 4188 }
}
```

### 4. 读取结果并验收

1. **检查状态**：只有 2xx 表示请求成功；4xx 检查参数和权限，5xx 或超时先确认请求是否已执行。
2. **读取结果**：从 `data[]` 取图片，GPT Image 返回 `data[].b64_json`，兼容模型可能返回 `data[].url`；不要假定一定有第一项。
3. **保存图片**：Base64 先解码为二进制，并按实际 MIME 类型选择扩展名；URL 及时下载，下载时不要附带 API Key。
4. **验收**：检查文件能否打开、实际像素尺寸、透明效果和内容，再核对使用日志。HTTP 200、空 `data[]` 或流式中间预览都不等于最终图片已经保存。

## 四、图片规格与计费

### 请求里各项规格分别控制什么

| 规格    | 含义与例子                              | 容易混淆的地方                                    |
| ----- | ---------------------------------- | ------------------------------------------ |
| 像素尺寸  | 实际宽 × 高，例如 `1024x1024`、`1536x1024` | 不是文件大小，也不自动代表质量档位                          |
| 宽高比   | `1:1` 方图、`16:9` 横图、`9:16` 竖图       | 相同比例可有多种分辨率；只选比例没有指定全部像素尺寸                 |
| 分辨率档位 | 某些模型使用 `1K`、`2K`、`4K` 等原生参数        | 厂商档位的实际宽高还取决于模型和比例，不应直接等同本站按张计费的像素边界       |
| 生成质量  | 如 OpenAI 的 `quality`，控制模型的渲染质量选择   | 不是 `size`，也不是 JPEG/WebP 的压缩质量；不同模型不一定有同名参数 |
| 文件格式  | PNG、JPEG、WebP 等，以实际返回的 MIME 类型为准   | Base64 和 URL 是交付方式，不是图片格式；改扩展名不能转换格式       |
| 透明背景  | 图片包含透明通道，适合素材叠加                    | 需要模型、参数和文件格式共同支持；写“透明背景”不保证结果一定带透明通道       |
| 张数    | 生成数量或候选数量，字段和上限随协议、模型变化            | 提示词写“生成三张”不等于设置 API 张数；多图输入也不等于多图输出        |

同一宽高比下，边长翻倍会让总像素数变为四倍，但不保证画面细节或清晰度按同样倍数提升。选择时先满足使用场景，再核对模型支持、耗时与价格，不必一律使用最高档。

具体字段、可用值和代码示例分别见 [OpenAI 请求格式](/simidoc/zh/apps/api/images/openai/generations)、[Gemini 请求格式](/simidoc/zh/apps/api/images/gemini/generate)、[通义千问请求格式](/simidoc/zh/apps/api/images/qwen/generations)、[即梦请求格式](/simidoc/zh/apps/api/images/jimeng)、[Grok 请求格式](/simidoc/zh/apps/api/images/grok)、[FLUX 请求格式](/simidoc/zh/apps/api/images/flux)。其中 OpenAI 的输出质量、格式和透明参数见[官方输出设置](https\://developers.openai.com/api/docs/guides/image-generation#customize-image-output)；Qwen 的尺寸与输出要求见[官方规格](https\://www.alibabacloud.com/help/en/model-studio/qwen-image-api)。不要把某个协议的参数直接复制给另一协议。

### 本站 1K、2K、4K 按张计费有什么区别

只有在[模型价格](https://api.dwchainless.com/zh/pricing/)中明确采用 1K / 2K / 4K 三档按张计费的模型，才适用下表。按 Token 计费或其他固定单价的模型仍按各自规则结算，不能仅凭“图片模型”名称判断收费方式。

| 计费档位 | 最长边                    | 示例尺寸（像素）            |
| ---- | ---------------------- | ------------------- |
| 1K   | 两边均 ≤ 1024 像素          | 1024×1024           |
| 2K   | 最长边 > 1024 且 ≤ 2048 像素 | 1280×720、1536×1024  |
| 4K   | 任一边 > 2048 像素          | 2560×1440、3840×2160 |

**总价 = 当前档位单张价格 × 计费张数。** 支持按完成结果结算的接口按实际完成张数计费；流式中间预览不算完成图片。单张价格、分组和最终扣费以当前模型价格及使用日志为准，本页不固定价格数值。

采用上述三档按张规则时，只有在未指定其他有效尺寸档位的情况下，省略 `size` 或使用 `auto` 才默认按 1K 档计费；显式指定的原生分辨率字段仍决定计费档位。按以下边界归档：1K 为两边均 ≤ 1024；2K 为最长边 > 1024 且 ≤ 2048；4K 为任一边 > 2048。例如 `1280x720` 属于 2K，`2560x1440` 属于 4K。

**计费档位不是输出尺寸承诺。** Gemini 的 `generationConfig.imageConfig.imageSize` 是模型的原生分辨率选择，实际像素尺寸应结合模型与比例确认；本站按支持的请求字段计算计费档位，不据此承诺统一的输出宽高。不要同时填写相互冲突的尺寸字段，也不要把按张规则套用到官方直连或按 Token 计费模型。

### size 的三种正确写法

部分 OpenAI 兼容网关支持以下写法；字段是否生效取决于模型与渠道，不被支持时应退回明确像素。

| 写法       | 请求片段                               | 用途               |
| :------- | :--------------------------------- | :--------------- |
| 明确像素（推荐） | `{"size":"1536x2048"}`             | 最直观，避免预设换算差异     |
| 比例 + 分辨率 | `{"size":"3:4","resolution":"2k"}` | 按 2K / 3\:4 预设换算 |
| 自动尺寸     | `{"size":"auto"}`                  | 由模型按能力选择，不承诺固定宽高 |

* K 档位填 `resolution`，`size` 填像素或比例；不要把 `2k` 写进 `size`。
* 尺寸分隔符使用小写英文字母 `x`，不要用乘号 ×、大写 X、数组或带乘号的字符串。
* 比例写进 `size` 时优先于单独的 `aspect_ratio`；明确像素或 `auto` 优先于比例预设。
* OpenAI 官方对 gpt-image-2 的任意尺寸上限为 3840×2160；`1:4`、`4:1` 的 4K 组合超过该上限，因此标注超出单边上限。其他模型的上限以模型说明为准。
* Gemini 与 Qwen 使用各自的尺寸字段，不能直接套用上述写法。
