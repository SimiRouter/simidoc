# Appels d’outils de fonction

## Description de l’interface

`POST /v1/chat/completions` utilise tools pour indiquer au modèle les fonctions disponibles. Le modèle génère seulement noms et arguments ; l’application valide, autorise et exécute, puis renvoie les résultats via des messages tool et demande la réponse finale. L’appel de fonction ne consulte pas à lui seul une base de données, n’effectue pas de virement et n’envoie pas de notification.

Adresse d’intégration \: `https://api.dwchainless.com`, avec l’en-tête `Authorization: Bearer $SIMIROUTER_API_KEY`. L’API directe officielle OpenAI est `https://api.openai.com`. Authentification \: Bearer avec une clé OpenAI. Choisissez un modèle accessible au compte et prenant en charge la capacité voulue.

## Paramètres de requête

| Champ                         | Type            | Obligatoire  | Description                                                                                                                |
| ----------------------------- | --------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| model / messages              | string / array  | Oui          | Modèle et conversation ; le modèle doit accepter les outils de fonction.                                                   |
| tools\[].type                 | string          | Oui          | Ici, function.                                                                                                             |
| tools\[].function.name        | string          | Oui          | Nom de fonction pour la répartition selon une liste d’autorisation applicative.                                            |
| tools\[].function.description | string          | Non          | Décrit l’usage, les limites d’entrée et les effets de bord.                                                                |
| tools\[].function.parameters  | object          | Oui          | JSON Schema des arguments de fonction.                                                                                     |
| tools\[].function.strict      | boolean         | Non          | À true, exige une correspondance stricte avec le sous-ensemble Schema accepté.                                             |
| tool\_choice                  | string / object | Non          | auto laisse le choix ; none désactive ; required exige au moins un appel ; une fonction peut aussi être nommément imposée. |
| parallel\_tool\_calls         | boolean         | Non          | Autorise plusieurs appels dans le même tour ; false limite à un appel au maximum.                                          |
| messages\[].tool\_call\_id    | string          | Conditionnel | Le message tool renvoyé doit correspondre à l’id des tool\_calls de l’assistant.                                           |
| messages\[].content           | string          | Conditionnel | Résultat du message tool, de préférence sérialisé en texte JSON.                                                           |

Avec strict=true, chaque objet exige additionalProperties=false et tous les champs de properties dans required. Les champs logiquement facultatifs peuvent accepter null ; un Schema refusé provoque une erreur de requête.

### Première requête

```json
{
  "model": "MODEL_ID",
  "messages": [
    {
      "role": "user",
      "content": "请计算17乘以23。"
    }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "multiply_numbers",
        "description": "将两个整数相乘。",
        "strict": true,
        "parameters": {
          "type": "object",
          "properties": {
            "a": {
              "type": "integer"
            },
            "b": {
              "type": "integer"
            }
          },
          "required": [
            "a",
            "b"
          ],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": "auto",
  "parallel_tool_calls": false,
  "stream": false
}
```

## Valeur de retour

| Champ                                | Type          | Description                                                                                                 |
| ------------------------------------ | ------------- | ----------------------------------------------------------------------------------------------------------- |
| choices\[].message.tool\_calls\[].id | string        | ID d’appel d’outil, à utiliser ensuite comme tool\_call\_id.                                                |
| tool\_calls\[].type                  | string        | function.                                                                                                   |
| tool\_calls\[].function.name         | string        | Nom de fonction demandée, devant correspondre à la liste d’autorisation de l’application.                   |
| tool\_calls\[].function.arguments    | string        | Texte JSON, pas un objet déjà analysé ; analysez-le puis contrôlez types et valeurs.                        |
| choices\[].message.content           | string / null | Peut être null lors d’un appel de fonction.                                                                 |
| choices\[].finish\_reason            | string        | tool\_calls signale des outils à exécuter ; stop indique généralement la réponse finale en langage naturel. |
| usage                                | object        | Chaque requête au modèle produit sa propre utilisation de tokens.                                           |

```json
{
  "id": "chatcmpl_tool_example",
  "object": "chat.completion",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_example",
            "type": "function",
            "function": {
              "name": "multiply_numbers",
              "arguments": "{\"a\":17,\"b\":23}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ]
}
```

### Exécution et renvoi

L’application doit vérifier name=multiply\_numbers et que a et b sont des entiers dans la plage autorisée ; le résultat est 391. Voici la seconde requête complète \: remplacez call\_example par l’ID réel reçu au premier tour ; ne réutilisez pas un ID statique pour exécuter des requêtes quelconques.

```json
{
  "model": "MODEL_ID",
  "messages": [
    {
      "role": "user",
      "content": "请计算17乘以23。"
    },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_example",
          "type": "function",
          "function": {
            "name": "multiply_numbers",
            "arguments": "{\"a\":17,\"b\":23}"
          }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "call_example",
      "content": "391"
    }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "multiply_numbers",
        "description": "将两个整数相乘。",
        "strict": true,
        "parameters": {
          "type": "object",
          "properties": {
            "a": {
              "type": "integer"
            },
            "b": {
              "type": "integer"
            }
          },
          "required": [
            "a",
            "b"
          ],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": "none",
  "stream": false
}
```

Chaque tool\_call doit recevoir un résultat ; n’en oubliez pas et ne mélangez pas les ID de conversations différentes. Seuls les outils indépendants et autorisés peuvent s’exécuter en parallèle. Les envois externes, débits et autres effets de bord exigent leur propre contrôle d’idempotence ; une nouvelle demande du modèle ne justifie pas une double exécution.

### Différences du format Responses

Dans Responses, la fonction est définie directement par type, name, description, parameters et strict de tools\[], sans enveloppe function. La sortie a type=function\_call et le résultat est renvoyé avec `{"type":"function_call_output","call_id":"...","output":"391"}`. Ne confondez pas tool\_call\_id de Chat et call\_id de Responses.

## Exemples de code

Les quatre exemples exécutent automatiquement une multiplication locale sans effet de bord et renvoient son résultat, en deux requêtes maximum, sans boucle infinie. Définissez `SIMIROUTER_API_KEY`, `SIMIROUTER_MODEL` ; `SIMIROUTER_BASE_URL` permet de remplacer l’adresse de la passerelle par défaut ; n’y ajoutez pas `/v1`. Les exemples Python 3, Node.js 18+ et Go utilisent uniquement la bibliothèque standard. L’exemple curl fait encoder le JSON de façon sûre par Python 3.

            raise ValueError("参数须为绝对值不超过1000000的两个整数")

    if assistant.get("tool_calls"):
        body["tool_choice"] = "none"
        request.data = json.dumps(body).encode("utf-8")
        try:
            with urllib.request.urlopen(request, timeout=120) as response:
                result = json.load(response)
        except urllib.error.HTTPError as error:
            print(f"HTTP {error.code}: {error.read().decode()}", file=sys.stderr)
            raise SystemExit(1)
    print(json.dumps(result, ensure_ascii=False, indent=2))

## Codes d’erreur

| Statut HTTP | Signification ou type d’erreur du fournisseur  | Traitement                                                                                                                       |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 400         | Requête invalide                               | Vérifiez les champs obligatoires, le JSON, les paramètres du modèle et la longueur du contexte.                                  |
| 401         | Échec de l’authentification                    | Vérifiez que la clé est présente, valide et rattachée au bon compte.                                                             |
| 403 / 404   | Accès interdit / ressource introuvable         | Vérifiez les autorisations du modèle, l’ID de ressource et l’URL.                                                                |
| 429         | Limite de débit ou de quota                    | Distinguez limitation de débit et crédit insuffisant à l’aide du corps de réponse ; réessayer ne résout pas un manque de crédit. |
| 500 / 503   | Erreur de service / indisponibilité temporaire | Conservez l’identifiant de requête et limitez les nouvelles tentatives avec attente progressive aux erreurs temporaires.         |

Les erreurs natives OpenAI contiennent généralement `error.message`, `error.type`, `error.param`, `error.code` ; `param`, `code` peuvent être `null` ; ne supposez pas que ces champs existent toujours ou correspondent au code HTTP. La passerelle peut renvoyer une erreur d’authentification, de routage ou de quota avant que la requête atteigne le fournisseur ; le seul code HTTP ne permet pas d’attribuer l’erreur à l’amont. Un échec d’analyse d’arguments, une fonction inconnue ou un échec métier relèvent de l’application \: ne simulez pas une exécution réussie. Une réponse HTTP réussie peut uniquement demander un outil, sans achever la tâche utilisateur.
