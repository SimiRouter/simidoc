Modération

Protocole officiel OpenAI de modération de texte et d’images.

Description de l’interface

POST https://api.openai.com/v1/moderations évalue de manière synchrone les catégories de sécurité du texte ou des images avec Authorization: Bearer $OPENAI_API_KEY. Routage, modèle et autorisations SimiRouter doivent être confirmés séparément ; les exemples ci-dessous utilisent directement OpenAI officiel.

Les résultats sont des signaux de risque, pas une conclusion de conformité juridique ni une garantie d’absence de faux négatifs. Les catégories prises en charge peuvent différer entre images et texte : examinez category_applied_input_types et ne déduisez pas l’innocuité d’une entrée non prise en charge.

Paramètres de requête

ChampTypeObligatoireDescription
modelstringNonPar exemple omni-moderation-latest ; fixer un modèle précis peut réduire l’effet des changements d’alias.
inputstring / string[] / object[]OuiTexte ou éléments de contenu multimodal.
input[].typestringConditionneltext ou image_url.
input[].textstringConditionnelTexte à modérer.
input[].image_url.urlstringConditionnelURL d’image ou data URL respectant les exigences d’entrée du modèle.

Valeur de retour

ChampDescription
id / modelIdentifiant de requête et modèle de modération.
results[].flaggedIndique si au moins une catégorie signale un risque.
results[].categoriesBooléens par catégorie.
results[].category_scoresScores de catégorie ; ni jugement humain ni seuil invariant entre modèles.
results[].category_applied_input_typesTypes d’entrée applicables à chaque catégorie.

L’exemple omet les clés de catégorie ; la réponse réelle contient leur détail. Conservez les éléments de preuve nécessaires, sans stocker indéfiniment tous les textes originaux des utilisateurs.

Exemples de code

L’exemple Python nécessite python3 -m pip install requests ; Node.js 18+ utilise fetch intégré et Go sa bibliothèque standard.

Définissez OPENAI_API_KEY.

Codes d’erreur

Statut HTTPSens et traitement
400 / 422Champs, média ou paramètres de modèle invalides ; corrigez avant de soumettre.
401Clé API absente, invalide ou expirée.
403Projet ou modèle non autorisé.
404Modèle ou route introuvable ; vérifiez l’adresse et le projet propriétaire.
413 / 415Fichier trop volumineux ou type de média non pris en charge.
429Limite de débit ou de quota ; distinguez le manque de crédit d’une limitation temporaire.
500 / 502 / 503 / 504Erreur du service ou de l’amont : conservez l’ID, examinez le corps de la réponse, puis décidez s’il faut réessayer.

Dans le corps d’erreur, error.message, error.type, error.code précisent mieux la cause que le statut HTTP. Ne prenez pas le corps d’erreur pour un résultat de modération.
