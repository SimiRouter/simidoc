Claude Messages

使用 Anthropic Messages 通訊協定完成對話、內容塊與工具呼叫。

介面說明

POST /v1/messages 接收 user/assistant 訊息，回傳由文字、工具呼叫或思考塊組成的 Message。頂層 system 用於系統指令，不要建立 role=system 的 messages 項。

串接位址為 https://api.dwchainless.com，請求標頭使用 Authorization: Bearer $SIMIROUTER_API_KEY。Anthropic 官方直連為 https://api.anthropic.com，使用 x-api-key: $ANTHROPIC_API_KEY。範例固定 anthropic-version: 2023-06-01 以選擇相應通訊協定版本，不代表最新版。 模型名稱應選用帳戶可存取且支援目標能力的模型。

快速開始

  1. 準備設定：在 API 金鑰管理 建立金鑰，從模型與價格複製支援 Claude Messages 的完整模型 ID。
  2. 傳送最小請求：只提交一則使用者訊息，保留 anthropic-version 請求標頭，stream 保持 false。
  3. 讀取結果：HTTP 2xx 且 content[] 非空才算成功，正文位於 type=text 的內容區塊。
  4. 驗收：檢查 stop_reason、stop_sequence 與實際內容，再核對使用記錄。

把 PASTE_API_KEY_HERE 和 MODEL_ID 換成實際值；anthropic-version 用於選擇協定版本，不代表最新版。

請求參數

請求主體為 JSON；範例請求標頭包含 anthropic-version: 2023-06-01。

欄位型別必填說明
modelstring是可存取的 Claude 模型 ID。
max_tokensinteger是生成 Token 上限；普通生成設為正整數，0 僅用於支援該行為的快取寫入流程。
messagesarray是對話訊息清單。
messages[].rolestring是user 或 assistant。
messages[].contentstring / array是文字字串或內容塊陣列。
content[].typestring條件text、image、tool_use、tool_result 等對應型別。
content[].textstring條件text 塊的本文。
content[].sourceobject條件image 的來源，可用 base64 的 media_type/data 或 url 型別的 url。
systemstring / array否系統指令；支援時可使用文字塊。
streamboolean否true 回傳 SSE；預設非串流。
stop_sequencesarray否自訂停止序列。
temperature / top_p / top_knumber / integer否取樣設定，僅對支援該設定的模型使用。
toolsarray否函式工具定義，包含 name、description、input_schema。
tool_choiceobject否auto、any、tool 或 none 等工具選擇；使用 tool 時指定 name。
thinkingobject否思考設定與模型代際有關；adaptive、enabled 等不是所有模型都接受。
metadata.user_idstring否業務使用者識別碼，不應傳送直接身分資訊。

請求範例

回傳值

HTTP 200 的非串流回應為 Message。

欄位型別說明
id / typestring訊息 ID；type=message。
role / modelstringassistant 與回應模型 ID。
content[]array內容塊清單；不能假定每一項都含 text。
content[].type / textstringtype=text 時讀取 text；tool_use 時讀取 id/name/input。
stop_reasonstring / nullend_turn 自然結束；max_tokens 達到上限；stop_sequence 命中停止串；tool_use 請求執行工具。
stop_sequencestring / null命中的停止序列，無則為 null。
usage.input_tokens / output_tokensinteger輸入與輸出 Token。
usage.cache_creation_input_tokens / cache_read_input_tokensinteger選用快取寫入與命中計量，不能簡單算作額外本文。

串流回應

stream=true 後依次處理 message_start、content_block_start、content_block_delta、content_block_stop、message_delta、message_stop。text_delta 追加文字；input_json_delta 追加工具參數的 partial_json，串接完成後才解析。message_delta 提供停止原因與用量更新，message_stop 標記訊息結束；error 事件可出現在 HTTP 200 之後。

工具使用時保留收到的助手內容塊，在後續 user 訊息中用 {"type":"tool_result","tool_use_id":"...","content":"..."} 回傳結果。執行工具前必須驗證參數與權限。

程式碼範例

設定 SIMIROUTER_API_KEY、SIMIROUTER_CLAUDE_MODEL；SIMIROUTER_BASE_URL 可覆蓋預設閘道位址，不要在末尾追加 /v1。 Python 3、Node.js 18+ 和 Go 範例只使用標準函式庫；curl 範例的 JSON 由 Python 3 安全編碼。

錯誤碼

HTTP 狀態含義或廠商錯誤型別處理方式
400invalid_request_error請求結構、參數或模型能力不匹配。
401 / 403authentication_error / permission_errorKey 無效或沒有存取權限。
404not_found_error端點、模型或資源不存在。
413request_too_large縮小請求主體。
429rate_limit_error檢查速率與額度限制。
500 / 504 / 529api_error / timeout_error / overloaded_error服務異常、逾時或過載；僅對暫時故障有限重試。

Anthropic 原生錯誤形如 {"type":"error","error":{"type":"invalid_request_error","message":"..."},"request_id":"..."}。 閘道可能在請求到達廠商前回傳驗證、路由或額度錯誤；不得僅憑 HTTP 數字判定錯誤來自上游。

長回覆與串流請求可能持續數十秒到數分鐘；用戶端應設定足夠逾時，斷流時依已收到的增量與終止原因判斷，不要自動重送。429 與 5xx 先查看回應內容與使用記錄，內容策略拒絕時修改提示詞或輸入，不要原樣重試。
