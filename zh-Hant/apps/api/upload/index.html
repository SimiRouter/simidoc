檔案與內容識別

區分行內檔案輸入、檔案上傳資源與非同步檔案處理。

檔案相關流程有兩層：上傳 API 管理檔案資源，模型輸入 API 讀取檔案內容並生成答案。把檔案附加到生成請求不等於將它儲存為可重複使用的檔案資源。

概覽

你要做的事輸入方式檔案去哪是否需要先上傳
讓模型讀一份 PDF請求行內 Base64 或可存取 URL只存在於本次請求否
在多輪請求中重複使用檔案file_id 或廠商檔案引用廠商檔案資源是（官方 Files API）
批次或超長檔案預處理上傳後等待處理完成廠商檔案資源是，且有生命週期

核心概念

  • 行內輸入：檔案編碼進請求體隨訊息發送，請求結束即結束，沒有 file_id，也沒有後續刪除步驟。
  • 檔案資源：先上傳取得 id，再在多次請求中引用；資源有歸屬、有效期和配額，需要顯式刪除。
  • 生命週期：上傳完成不等於文字抽取完成，也不等於模型已經理解；輪詢到可處理狀態後才能推理。
  • 大小與格式：限制按檔案大小、頁數、時長分別設定；壓縮圖片不會轉換檔案類型，掃描版 PDF 還需要 OCR 能力。
  • 資料保留：各廠商對檔案內容與識別結果的保留策略不同，敏感材料先確認授權與刪除方式。

請求與能力

用途請求邊界
PDF 內容識別POST /v1/responses + input_file行內 Base64，無需 Files API。
Chat PDF 輸入POST /v1/chat/completions + type=file使用 Chat 的 file 物件，不是 Responses 結構。
Files API/v1/files閘道未實現；官方原生上傳能力不代表本站開放。
Gemini 媒體理解POST /v1beta/models/{model}:generateContentinlineData 或適用的 fileData。

呼叫方式

行內識別可同步回傳 JSON，也可串流回傳文字事件；均屬於一次模型請求。官方某些上傳或檔案預處理流程需要等待資源可用，屬於資源生命週期，不等於模型自動背景執行。多檔案可以在一個支援的請求里提交，也可以分成平行請求；兩種方式的上下文、費用和總大小限制不同。

上傳敏感檔案前確認處理授權與服務商資料政策。大型文件宜按任務選擇相關頁或片段，不要為追求一次完成無限增加輸入。識別輸出必須保留不確定性，關鍵金額、編號與法律醫療結論應人工複核。
