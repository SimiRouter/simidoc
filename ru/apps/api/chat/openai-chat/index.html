Chat Completions

Текст, мультимодальность, функции и SSE через список сообщений.

Описание интерфейса

POST /v1/chat/completions генерирует ответ по истории сообщений. Подходит существующим клиентам Chat Completions и диалогам с явно передаваемой историей.

Адрес подключения — https://api.dwchainless.com, заголовок — Authorization: Bearer $SIMIROUTER_API_KEY. Прямой OpenAI — https://api.openai.com; также Bearer, но нужен ключ OpenAI. Выберите доступную модель с поддержкой требуемой функции.

Быстрый старт

  1. Подготовьте конфигурацию: создайте ключ в разделе Управление API-ключами и скопируйте полный ID модели с поддержкой Chat Completions из раздела Модели и цены.
  2. Отправьте минимальный запрос: передайте одно сообщение пользователя и оставьте stream равным false; сначала убедитесь, что аутентификация, модель и параметры корректны.
  3. Прочитайте результат: запрос успешен, только если HTTP 2xx и choices[] не пуст; текст находится в choices[0].message.content.
  4. Проверьте: сверьте finish_reason, отказы и фактическое содержимое, затем проверьте журнал использования.

Замените PASTE_API_KEY_HERE и MODEL_ID на реальные значения; после успешной проверки добавьте историю диалога, инструменты или включите потоковую передачу.

Если проект уже использует OpenAI SDK, укажите в baseURL адрес https://api.dwchainless.com/v1 и ключ SimiRouter; имена методов и параметры не меняются. См. Скрипты вызова API.

Тип содержимого — application/json. Неиспользуемые поля опускайте, а не отправляйте пустые строки, 0, пустые объекты и null.

Пример запроса

Ответ

Успешный непотоковый ответ: HTTP 200 JSON. ID и числа токенов ниже иллюстрируют структуру.

ПолеТипОписание
id / objectstringID ответа; object=chat.completion.
created / modelinteger / stringВремя Unix в секундах и модель ответа.
choices[]arrayКандидаты, позиция каждого задается index.
choices[].message.rolestringassistant.
choices[].message.contentstring / nullТекст; при инструментах или отказе может отсутствовать, это не обязательно ошибка запроса.
choices[].message.tool_callsarrayФункции для выполнения приложением. arguments — JSON-строка, которую нужно разобрать и проверить.
choices[].message.refusalstring / nullОтказ, если имеется.
choices[].finish_reasonstringstop — конец, length — лимит, tool_calls — вызов инструмента, content_filter — фильтрация.
usage.prompt_tokensintegerВходные токены.
usage.completion_tokensintegerСгенерированные токены, включая возможные рассуждения.

Потоковый ответ

Задайте stream: true, чтобы получить text/event-stream. Разбирайте JSON строк data: по choices[].index и объединяйте delta.content; аргументы функций объединяйте по индексу инструмента delta.tool_calls. Маркер завершения — data: [DONE], не JSON. При include_usage итоговый choices может быть пустым, а usage промежуточных блоков — null. Разрыв без маркера означает неполный ответ, а не успех.

Примеры вызова

Задайте SIMIROUTER_API_KEY, SIMIROUTER_MODEL; SIMIROUTER_BASE_URL переопределяет адрес шлюза по умолчанию; не добавляйте в конец /v1. Примеры Python 3, Node.js 18+ и Go используют только стандартную библиотеку; JSON в примере curl безопасно формируется Python 3.

Использование OpenAI SDK

Если установлен официальный SDK openai, писать HTTP-запросы вручную не нужно: укажите в baseURL адрес шлюза, чтобы использовать официальные типы, повторы и разбор потока. Установка: pip install openai или npm install openai.

Коды ошибок

Статус HTTPЗначение или тип ошибки провайдераДействие
400Неверный запросПроверьте обязательные поля, JSON, параметры модели и длину контекста.
401Ошибка аутентификацииПроверьте наличие, действительность и принадлежность ключа.
403 / 404Нет доступа / ресурс не найденПроверьте права модели, ID ресурса и URL.
429Ограничение частоты или квотыРазличайте лимит скорости и нехватку квоты по ответу; повтор не восполняет квоту.
500 / 503Ошибка сервиса / временная недоступностьСохраните ID и ограниченно повторите временные сбои с задержкой.

Ошибка OpenAI обычно содержит error.message, error.type, error.param, error.code; param и code могут быть null; поля необязательны и не обязаны равняться HTTP-статусу. Шлюз может отказать до провайдера; по числу HTTP нельзя установить источник ошибки. При 200 проверяйте finish_reason, отказ и целостность потока; length/content_filter не являются HTTP-ошибками.

Длинные ответы и потоковые запросы могут длиться от десятков секунд до нескольких минут; задайте достаточный тайм-аут клиента и при обрыве потока оценивайте полученные фрагменты и причину завершения, а не отправляйте запрос повторно автоматически. При 429 и 5xx сначала проверьте тело ответа и журнал использования; при отказе по политике содержимого измените запрос или входные данные, а не повторяйте запрос без изменений.

Частые вопросы

Что делать при 401 или Invalid token? Проверьте, что заголовок — Authorization: Bearer <Key>, ключ принадлежит этому шлюзу и не отозван, а также что вы не вставили пароль от аккаунта или ключ провайдера.

Почему возвращается 404 или «модель не найдена»? model должен быть полным идентификатором из Каталога и цен, а группе вашего ключа должен быть разрешён доступ. Пользователям SDK стоит также проверить, что в baseURL есть /v1.

Стоит ли повторять запрос при 429? Сначала прочитайте тело ответа. При ограничении частоты повторяйте с экспоненциальной задержкой и джиттером; при исчерпанной квоте или балансе повтор не поможет — пополните счёт или измените лимит.

Когда потоковый ответ считается полным? Только после data: [DONE] и последнего блока с finish_reason. Если соединение оборвалось без маркера завершения, считайте ответ неполным и не отправляйте автоматически уже оплаченный запрос повторно.

max_tokens или max_completion_tokens? Для Chat Completions используйте max_completion_tokens. max_tokens — устаревшее поле, его принимают только некоторые модели. Не отправляйте оба; /v1/completions по-прежнему использует только max_tokens.

Почему temperature не действует? Некоторые reasoning-модели фиксируют сэмплирование или принимают только значения по умолчанию, а шлюз передаёт параметры провайдеру. Ориентируйтесь на документацию и ошибки модели, не считая, что все параметры OpenAI применимы.
