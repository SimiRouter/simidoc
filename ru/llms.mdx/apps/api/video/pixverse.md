# Видео PixVerse

## Обзор

Официальный OpenAPI PixVerse отправляет асинхронные задачи генерации обычными HTTP-запросами\: после успешного создания возвращается `video_id`, затем по тому же ID запрашивается состояние и получается адрес видео. Генерация по тексту и генерация по изображению — два отдельных входа; для генерации по изображению сначала нужно загрузить изображение, получить `img_id` и только потом отправлять задачу.

| Что нужно сделать            | Ввод                                                                  | Вывод                                         | Эндпоинт                                  |
| ---------------------------- | --------------------------------------------------------------------- | --------------------------------------------- | ----------------------------------------- |
| Создать видео по тексту      | Промпт, длительность, `quality`, `aspect_ratio`                       | `video_id`                                    | `POST /openapi/v2/video/text/generate`    |
| Создать видео по изображению | `img_id` загруженного изображения (или `img_ids` шаблона) плюс промпт | `video_id`                                    | `POST /openapi/v2/video/img/generate`     |
| Запросить результат задачи   | `video_id`                                                            | Статус, URL видео, фактические характеристики | `GET /openapi/v2/video/result/{video_id}` |
| Загрузить изображение        | Файл изображения                                                      | `img_id`                                      | `POST /openapi/v2/image/upload`           |

## Ключевые понятия

* **Жизненный цикл задачи**\: создание возвращает `ErrCode=0` и `video_id`, что означает только приём задачи. Статус запроса `1` — завершено, `5` — генерация идёт, `7` — ошибка модерации контента, `8` — ошибка генерации; `1`, `7`, `8` — конечные состояния.
* **Два ID имеют разное назначение**\: `video_id` — идентификатор бизнес-задачи, используется для запроса и скачивания; `Ai-trace-id` — UUID, который нужно генерировать заново для каждого запроса, он служит только для трассировки и не является ключом идемпотентности; повторное использование может создать ещё одну задачу.
* **Ритм опроса**\: официально рекомендуется запрашивать каждые 3–5 секунд. Клиент должен задавать общий предел ожидания; после перехода в `7` или `8` немедленно останавливайтесь и не повторяйте попытки для той же задачи.
* **Единица тарификации**\: `Resp.credits` в ответе создания — это кредиты, израсходованные этой задачей. Фактическая цена за единицу, тариф и правила возврата определяются страницей цен провайдера и счётом аккаунта.
* **Кадр и длительность управляются раздельно**\: для генерации по тексту `quality` задаёт уровень чёткости, а `aspect_ratio` — формат кадра; у генерации по изображению нет поля `aspect_ratio`, формат определяется входным изображением или шаблоном. Допустимые значения `duration` зависят от модели; нельзя заполнять только по диапазону 1–15 из интерфейса.

## Характеристики и возможности

| Показатель              | Подтверждённые значения                                                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| ID модели               | `v6-max`, `c1`, `v6`, `v5.6`, `v5.5`, `v5`, `v5-fast`, `v4.5`, `v4`, `v3.5`; для `v5-fast` требуются права аккаунта                           |
| Разрешение              | `quality`\: `360p`, `540p`, `720p`, `1080p`                                                                                                   |
| Соотношение сторон      | Текст в видео\: `16:9`, `9:16`, `4:3`, `3:4`, `1:1`, `2:3`, `3:2`, `21:9`; изображение в видео\: поля нет                                     |
| Длительность            | Диапазон интерфейса 1–15 секунд; C1 и V6 — 1–15 секунд, V5.5 и V5.6 — 5, 8 или 10 секунд, старые модели — 5 или 8 секунд                      |
| Аудио                   | Логический переключатель `generate_audio_switch`, по умолчанию `false`; V5.5, V5.6, V6 и C1 поддерживают нативный звук                        |
| Референсное изображение | Для генерации по изображению сначала загрузите изображение и получите `img_id`; задачи по шаблону используют `img_ids` вместе с `template_id` |
| Учёт тарификации        | Ответ создания возвращает `Resp.credits`; цена за единицу — по странице цен провайдера                                                        |

При выборе сначала смотрите на поколение модели, затем на `quality` и `duration`. `quality` определяет только уровень пикселей вывода и не меняет формат кадра; `aspect_ratio` определяет только форму, а итоговые пиксели задаются обоими параметрами вместе. У генерации по изображению нет поля `aspect_ratio`; не копируйте тело запроса генерации по тексту, формат кадра определяется входным изображением или шаблоном. `Resp.credits` из ответа создания подходит для записи бюджета, но фактическое списание и возврат по-прежнему определяются счётом аккаунта.

## Процесс вызова

1. Создайте API Key на открытой платформе PixVerse. В запросах используется заголовок `API-KEY`; не записывайте его в промпт или репозиторий кода.
2. Для генерации по изображению сначала вызовите `POST /openapi/v2/image/upload`, загрузите изображение и сохраните `Resp.img_id` из ответа; для генерации по тексту этот шаг пропускается.
3. Отправьте JSON на соответствующий эндпоинт генерации. Обязательные поля — `model`, `prompt`, `duration`, `quality`; для генерации по тексту также нужен `aspect_ratio`. Для каждого запроса создавайте новый `Ai-trace-id`.
4. Сохраните `Resp.video_id` из ответа создания. Не считайте `ErrCode=0` доказательством того, что видео уже создано.
5. Каждые 3–5 секунд вызывайте эндпоинт запроса. Скачивайте только при `status=1` и доступном `Resp.url`; при `status=7` исправьте содержимое и затем решайте, повторять ли попытку; при `status=8` сохраните `Ai-trace-id` для диагностики.
6. Сохраните видео в собственное хранилище. Политика доступа и срок действия URL результата определяются провайдером; не считайте его постоянным публичным адресом.

## Имитация вызова

Приведённые ниже сообщения только иллюстрируют структуру полей; ID задач, кредиты и URL — примерные значения, а не реальные данные аккаунта.

Создание задачи генерации по тексту\:

```json
{
  "model": "v6-max",
  "prompt": "示例：海边日落，一艘白色帆船缓慢驶过，镜头平稳。",
  "duration": 5,
  "quality": "720p",
  "aspect_ratio": "16:9",
  "seed": 20260804,
  "generate_audio_switch": false
}
```

Успешное создание возвращает только ID задачи и израсходованные кредиты\:

```json
{
  "ErrCode": 0,
  "ErrMsg": "Success",
  "Resp": {
    "video_id": 900000000000001,
    "credits": 12
  }
}
```

Адрес для скачивания доступен только после запроса с `status=1`\:

```json
{
  "ErrCode": 0,
  "ErrMsg": "Success",
  "Resp": {
    "id": 900000000000001,
    "status": 1,
    "url": "https://example.com/demo-pixverse.mp4",
    "duration": 5,
    "quality": "720p",
    "aspect_ratio": "16:9",
    "outputWidth": 1280,
    "outputHeight": 720,
    "has_audio": false,
    "credits": 12
  }
}
```

При `status=5` продолжайте опрос; при `status=7` или `status=8` немедленно завершайте и фиксируйте причину ошибки из `ErrMsg`, `Error.Message` и `Ai-trace-id`.

## Подключение и сеансы

* **Базовый адрес**\: `https://app-api.pixverse.ai`. Генерация и запросы находятся под `/openapi/v2/`.
* **Заголовок аутентификации**\: `API-KEY: PASTE_API_KEY_HERE`; `Content-Type: application/json`; для каждого запроса добавляйте новый `Ai-trace-id`.
* **Два набора адресов**\: для прямого подключения используйте `https://app-api.pixverse.ai` с заголовком `API-KEY`; используйте `https://api.dwchainless.com` и `Authorization: Bearer` с ключом сайта только при явном подтверждении сопоставления с этим шлюзом; одной замены адреса и аутентификации недостаточно. То, отображает ли канал SimiRouter эти пути и переходит ли он на единый видеопротокол, зависит от конфигурации канала; нельзя предполагать совместимость полей только после замены домена.
* **Таймаут и идемпотентность**\: таймаут запроса создания не доказывает, что сервер не принял задачу. Сначала запросите по сохранённому `video_id` и повторяйте только после подтверждения, что задачи нет; не отправляйте один и тот же промпт подряд, чтобы «ускорить прогресс».
* **Определение ошибок**\: HTTP 200 тоже может содержать ненулевой `ErrCode`. Для бизнес-ошибок читайте `ErrCode`, `ErrMsg` и необязательные `Error.Type`, `Error.Param`, а не только HTTP-статус.
