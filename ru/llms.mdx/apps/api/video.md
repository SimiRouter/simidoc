# Видео

Видео делится на **генерацию** и **понимание**\: генерация создаёт новое видео из текста или референсов; понимание извлекает из готового видео резюме, события и текстовые ответы. Запросы, время выполнения и результаты полностью различаются.

## Обзор

| Возможность                          | Ввод                                   | Вывод                               | Порядок длительности                   |
| ------------------------------------ | -------------------------------------- | ----------------------------------- | -------------------------------------- |
| Текст в видео                        | Промпт                                 | Видеофайл или ссылка для скачивания | От десятков секунд до нескольких минут |
| Изображение в видео                  | Изображение первого кадра + промпт     | Видеофайл                           | От десятков секунд до нескольких минут |
| Управление первым и последним кадром | Изображения первого и последнего кадра | Видео с заданными началом и концом  | Несколько минут                        |
| Понимание видео                      | Видео + вопрос                         | Текстовое резюме или ответ          | Зависит от длительности видео          |

## Ключевые понятия

* **Разрешение**\: обычно 480p, 720p, 1080p. Оно определяет чёткость изображения и напрямую влияет на время генерации и цену; черновики и превью обычно поддерживают только пониженное разрешение.
* **Соотношение сторон**\: `16:9` горизонтальное, `9:16` вертикальное, `1:1` квадратное. Соотношение и разрешение вместе определяют фактические пиксели; например, вертикальное 1080p — это `1080x1920`.
* **Частота кадров (fps)**\: число кадров в секунду, обычно 24 или 30. Её повышение увеличивает файл и замедляет генерацию, но не обязательно делает движение естественнее.
* **Длительность**\: число секунд одного видеофрагмента с ограничением по модели. Некоторые модели принимают число кадров вместо длительности; при одновременной передаче уточните в документации интерфейса, какой параметр приоритетен.
* **Референсы**\: изображения служат первым кадром, последним кадром или стилевым референсом; поддержка референсных видео и аудио сильно различается по моделям и не должна предполагаться по умолчанию.
* **Состояние задачи**\: ID, возвращённый при создании, означает только приём задачи. Настоящий успех определяется конечным состоянием интерфейса проверки и действительным адресом вывода; состояние вроде `done` не всегда означает успех.

Доступные значения и ограничения этих параметров определяются версией модели; смотрите таблицу параметров запроса на каждой подстранице и не переносите поля одной версии на другую.

## Процесс запроса

1. Запрос создания возвращает ID задачи, который означает только приём, а не готовность видео.
2. Используйте интерфейс проверки задачи того же провайдера/канала; делайте интервалы в несколько секунд и задавайте общий предельный срок ожидания. При ошибке, истечении срока или отмене немедленно прекращайте.
3. Скачивайте только после успешного конечного состояния и при наличии действительного видео. Сохраняйте исходный ID задачи, ID запроса и причину ошибки, а не только «HTTP 200».
4. URL результата часто имеет срок действия — своевременно сохраните файл. Ссылка для скачивания не является постоянным хранилищем.

Генерация видео обычно не использует SSE; опрос состояния не является потоком видео в реальном времени. Аудио, разрешение, длительность, первый и последний кадры и поддержка нескольких референсов зависят от версии модели; нельзя переносить поля одной версии на все видеомодели.

## Имитация вызова

В следующем примере используется протокол Seedance для демонстрации трёх этапов\: создания, приёма и проверки; содержимое приведено для иллюстрации, а адреса и аутентификация относятся к официальному прямому подключению Volcano Ark.

Запрос создания передаёт только промпт и параметры видео\:

```json
{
  "model": "doubao-seedance-2-5-260628",
  "content": [
    { "type": "text", "text": "海边日落，镜头缓慢推进" }
  ],
  "resolution": "720p",
  "ratio": "16:9",
  "duration": 5
}
```

Успешное создание возвращает только ID задачи, а не видео\:

```json
{"id":"cgt-example"}
```

Задача считается завершённой только после достижения конечного состояния и при наличии адреса результата\:

```json
{
  "id": "cgt-example",
  "status": "succeeded",
  "content": { "video_url": "https://example.com/video.mp4" },
  "error": null
}
```

Если состояние — `queued` или `running`, продолжайте ожидание; при `failed`, `expired` или `cancelled` немедленно прекратите опрос и сохраните `error`. Генерация видео не имеет инкрементов SSE; результат можно получить только опросом или обратным вызовом.

## Адреса провайдеров и SimiRouter

Подстраницы этого раздела приводят поля и порядок вызова по **официальному протоколу провайдера**. Тело запроса, путь и поля статуса в примерах сначала следует рассматривать как справочник для прямого доступа к провайдеру; адрес шлюза `https://api.dwchainless.com` и ключ SimiRouter используйте только там, где на странице явно подтверждено сопоставление со шлюзом. Открыта ли шлюзом модель с тем же именем, какой путь используется и как сопоставляются поля, определяют список моделей учётной записи и текущая конфигурация канала. Не отправляйте запрос провайдера на шлюз, просто заменив домен.

Ключи провайдера, Volcano AK/SK и ключи SimiRouter не взаимозаменяемы. Если для канала нет явного сопоставления, не запускайте платную генерацию, просто заменив домен.
