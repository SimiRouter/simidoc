# Files API (не поддерживается)

Files API — интерфейс управления файловыми ресурсами OpenAI. После загрузки вы получаете ID файла, который можно использовать в дообучении, пакетной обработке и других официальных эндпоинтах, принимающих ID файла. Это не то же самое, что способность модели распознавать содержимое файла.

**SimiRouter пока не поддерживает Files API. Следующие страницы сохраняют официальное описание и прямые примеры с обязательным ключом проекта OpenAI.**

## Обзор

Files API решает задачу «загрузить один раз, ссылаться многократно»\: файл сначала существует как отдельный ресурс, а затем используется эндпоинтами дообучения, пакетной обработки и другими по ID. Он подходит для обучающих наборов, тел пакетных запросов и материалов, которые нужно многократно читать; вложения в одном диалоге не используют этот интерфейс, а передаются прямо в запросе.

| Сценарий использования                 | Метка при загрузке       | Что делать после загрузки                             |
| -------------------------------------- | ------------------------ | ----------------------------------------------------- |
| Данные для обучения с учителем         | `purpose=fine-tune`      | Создать задачу обучения и опрашивать статус           |
| Пакетные запросы или вывод             | `purpose=batch`          | Создать задачу пакетной обработки и опрашивать статус |
| Другие эндпоинты, принимающие ID файла | По требованиям эндпоинта | Ориентироваться на документацию этого эндпоинта       |

## Ключевые понятия

* **ID файла и область действия**\: ID принадлежит создавшему его проекту или организации, его нельзя переиспользовать между поставщиками и проектами; если вставить ID файла другого сервиса в запрос OpenAI, будет 404 или 403.
* **purpose определяет назначение**\: `purpose` при загрузке указывает, кому будут использоваться данные (например, `fine-tune`, `batch`), а потребляющие эндпоинты дополнительно проверяют формат, размер и число строк.
* **Жизненный цикл**\: успешная загрузка означает лишь, что ресурс существует; завершено ли обучение или пакетная обработка, нужно проверять по статусу соответствующей задачи, а не судить по результату загрузки.
* **Содержимое и метаданные разделены**\: `filename`, `bytes`, `status` в объекте файла — это метаданные; содержимое, которое видит модель, читается потребляющим эндпоинтом, и эти данные не синхронизируются автоматически.

## Интерфейсы и выполнение

| Операция                                                      | Официальный запрос                | Способ выполнения                                        |
| ------------------------------------------------------------- | --------------------------------- | -------------------------------------------------------- |
| [Загрузить файл (не поддерживается)](/simidoc/ru/apps/api/pending/files/upload)                | `POST /v1/files`                  | Multipart-загрузка с синхронным возвратом объекта файла. |
| [Получить информацию о файле (не поддерживается)](/simidoc/ru/apps/api/pending/files/retrieve) | `GET /v1/files/{file_id}`         | Синхронный возврат метаданных.                           |
| [Список файлов (не поддерживается)](/simidoc/ru/apps/api/pending/files/list)                   | `GET /v1/files`                   | Синхронная постраничная выборка.                         |
| [Получить содержимое файла (не поддерживается)](/simidoc/ru/apps/api/pending/files/content)    | `GET /v1/files/{file_id}/content` | Скачивание байтов файла, а не SSE модели.                |
| [Удалить файл (не поддерживается)](/simidoc/ru/apps/api/pending/files/delete)                  | `DELETE /v1/files/{file_id}`      | Удаление ресурса с возвратом результата удаления.        |

Успешная загрузка файла не означает, что задача его использования завершена. Статус обучения, пакетной обработки и индексации проверяется через соответствующие эндпоинты. Назначение, формат и ограничения размера файла также определяются потребляющим эндпоинтом.

## Ресурсы и безопасность

ID файла принадлежит создавшему его проекту или организации; нельзя напрямую использовать в OpenAI ID файла другого поставщика или шлюза. Примеры читают ключ из переменных окружения; не публикуйте обучающие наборы, персональные данные или ключи в открытых репозиториях.
