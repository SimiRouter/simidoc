# Эмбеддинги (не поддерживаются)

**SimiRouter пока не поддерживает интерфейс эмбеддингов.** Раздел объясняет протоколы поставщиков; примеры работают только напрямую с соответствующим аккаунтом и ключом.

## Обзор

Эмбеддинги отображают текст или другие допустимые для модели входы в вектор фиксированной длины; они используются для семантического поиска, кластеризации и анализа сходства. Они не возвращают ответ чата и не выполняют поиск напрямую; процесс поиска обычно состоит из трёх этапов\: «отбор кандидатов по эмбеддингам + точное ранжирование реранжированием + генерация ответа моделью». Подробности эндпоинтов — в разделах [Эмбеддинги OpenAI](/simidoc/ru/apps/api/pending/embeddings/openai) и [Эмбеддинги Gemini](/simidoc/ru/apps/api/pending/embeddings/gemini).

| Что вы хотите сделать                           | Ввод                                              | Вывод                                                           | Эндпоинт                                                                            |
| ----------------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Сгенерировать вектор текста                     | Один или несколько текстов                        | Массив чисел с плавающей точкой фиксированной длины             | OpenAI `POST /v1/embeddings`; Google `POST /v1beta/models/{model}:embedContent`     |
| Сгенерировать вектор изображения и других медиа | Поддерживаемое моделью мультимодальное содержимое | Массив чисел с плавающей точкой в том же векторном пространстве | Только модели с поддержкой мультимодальности, например `gemini-embedding-2`         |
| Массово построить индекс                        | Несколько текстов                                 | Список векторов, выровненный по порядку ввода                   | `batchEmbedContents` или Batch API; асинхронные пакетные задачи выделяются отдельно |

## Ключевые понятия

* **Размерность**\: у OpenAI `text-embedding-3-small` по умолчанию 1536 измерений, у `text-embedding-3-large` по умолчанию 3072 измерения; Gemini Embedding 2 поддерживает 128–3072 измерений (рекомендуются 768, 1536 или 3072), а `gemini-embedding-001` по умолчанию использует 3072. Размерность можно уменьшать в пределах диапазона модели, но нельзя превышать её предел; оба провайдера напрямую связывают стоимость хранения и поиска в векторной базе с размерностью.
* **Нормализация и сходство**\: OpenAI возвращает векторы длиной 1, поэтому скалярное произведение равно косинусному сходству; Gemini при размерности, отличной от 3072, требует повторной нормализации (`gemini-embedding-2` делает это автоматически, а `gemini-embedding-001` — вручную). Векторная база должна использовать одну фиксированную метрику.
* **Индекс и запрос должны быть изоморфны**\: для одной партии документов и запросов нужно использовать одну модель, одну размерность и одну конфигурацию задачи. После смены модели или размерности старый индекс и новые векторы несопоставимы, индекс нужно перестраивать.
* **`index` — это не рейтинг**\: поле `index` в ответе лишь указывает, какому по счёту входу соответствует вектор, чтобы выровнять его с исходным текстом; сортировка по релевантности — задача реранжирования, см. [Реранжирование](/simidoc/ru/apps/api/pending/rerank).
* **Синхронность и пакетная обработка**\: эмбеддинги — синхронный запрос без SSE; для больших объёмов используйте Batch API или `batchEmbedContents`, не пытайтесь набрать объём циклом одиночных вызовов.

## Моделируемый вызов

Пример запроса и ответа для прямого доступа к OpenAI. При отправке запроса используйте ключ проекта `$OPENAI_API_KEY`.

```json
{
  "model": "text-embedding-3-small",
  "input": ["文档检索的第一段文本", "如何计算两段文本的相似度"]
}
```

```json
{
  "object": "list",
  "data": [
    { "object": "embedding", "index": 0, "embedding": [0.0023, -0.0119, 0.0044] },
    { "object": "embedding", "index": 1, "embedding": [0.0011, 0.0087, -0.0026] }
  ],
  "model": "text-embedding-3-small",
  "usage": { "prompt_tokens": 12, "total_tokens": 12 }
}
```

Фактический вектор содержит 1536 чисел с плавающей точкой, здесь оставлены только первые три; `usage` тарифицируется по входным токенам и не зависит от длины вывода.

## Основные моменты использования в поиске

Эти два ответа имеют разную структуру, заменить только имя модели недостаточно. Обычно нет SSE или Realtime; асинхронная пакетная задача также не является потоком векторов в реальном времени. Документы и запросы одной векторной базы должны использовать одинаковые модель, размерность и стратегию нормализации; после смены модели обычно требуется перестроить индекс.
