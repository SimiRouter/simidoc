# Файлы и распознавание содержимого

Есть два уровня\: API загрузки управляет файловыми ресурсами, а API ввода модели читает содержимое и генерирует ответ. Вложение файла в запрос генерации не означает сохранение повторно используемого файлового ресурса.

## Обзор

| Что нужно сделать                                           | Способ ввода                                | Куда попадает файл               | Нужна ли предварительная загрузка |
| ----------------------------------------------------------- | ------------------------------------------- | -------------------------------- | --------------------------------- |
| Дать модели прочитать PDF                                   | Base64 встроенно в запрос или доступный URL | Существует только в этом запросе | Нет                               |
| Повторно использовать файл в нескольких запросах            | file\_id или ссылка на файл провайдера      | Файловый ресурс провайдера       | Да (официальный Files API)        |
| Пакетная или предварительная обработка очень длинных файлов | Загрузить и дождаться завершения обработки  | Файловый ресурс провайдера       | Да, с жизненным циклом            |

## Ключевые понятия

* **Встроенный ввод**\: файл кодируется в тело запроса и отправляется вместе с сообщением; он существует только до конца запроса, без file\_id и без последующего удаления.
* **Файловый ресурс**\: сначала загрузите файл и получите id, затем ссылайтесь на него в нескольких запросах; у ресурса есть владелец, срок действия и квота, и его нужно удалять явно.
* **Жизненный цикл**\: завершение загрузки не означает ни завершения извлечения текста, ни того, что модель уже поняла файл; перед инференсом дождитесь опроса состояния, в котором файл можно обрабатывать.
* **Размер и формат**\: ограничения задаются отдельно по размеру файла, числу страниц и длительности; сжатие изображения не меняет тип файла, а сканированному PDF по-прежнему нужны возможности OCR.
* **Хранение данных**\: у провайдеров разные политики хранения содержимого файлов и результатов распознавания; для конфиденциальных материалов сначала уточните разрешение и способы удаления.

## Способ вызова

Встроенный ввод возвращает синхронный JSON либо поток текстовых событий; оба варианта — один запрос к модели. При некоторых официальных загрузках или предварительной обработке нужно дождаться готовности ресурса. Это жизненный цикл ресурса, а не автоматическое фоновое выполнение модели. Несколько файлов можно передать одним поддерживаемым запросом или независимыми параллельными запросами; контекст, оплата и суммарные ограничения размера различаются.

До загрузки конфиденциальных файлов проверьте разрешение на обработку и политику провайдера. Для больших документов выбирайте нужные страницы или фрагменты, а не неограниченно увеличивайте ввод. Сохраняйте неопределенность распознавания; суммы, идентификаторы, юридические и медицинские выводы требуют проверки человеком.

## Имитация вызова

Встроенное распознавание выполняется одним запросом; файл передаётся в Base64 в `input_file`\:

```json
{
  "model": "gpt-5.5",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "总结这份合同的付款条款。" },
        { "type": "input_file", "filename": "contract.pdf", "file_data": "data:application/pdf;base64,JVBERi0xLjQK..." }
      ]
    }
  ]
}
```

Ответ — обычное сообщение модели, результат находится в `output_text`\:

```json
{
  "status": "completed",
  "output": [
    {
      "type": "message",
      "content": [
        { "type": "output_text", "text": "（示意）合同约定分三期付款……" }
      ]
    }
  ]
}
```

В процессе нет этапа загрузки и нет повторно используемого file\_id; чтобы снова обратиться к тому же файлу, нужно повторно отправить Base64 или перейти на официальный файловый ресурс.
