# Генерация изображений BFL FLUX

## Обзор

FLUX API от Black Forest Labs использует асинхронную модель «отправка задачи + опрос результата». Запрос отправки возвращает только ID задачи и `polling_url`; подписанный URL читается из результата опроса только после завершения генерации изображения.

| Что нужно сделать                         | Ввод                        | Вывод                           | Эндпоинт                                         |
| ----------------------------------------- | --------------------------- | ------------------------------- | ------------------------------------------------ |
| Создать изображение по тексту             | `prompt`, `width`, `height` | ID задачи `id` и `polling_url`  | `POST https://api.bfl.ai/v1/flux-pro-1.1`        |
| Создать широкое изображение по пропорциям | `prompt`, `aspect_ratio`    | ID задачи `id` и `polling_url`  | `POST https://api.bfl.ai/v1/flux-pro-1.1-ultra`  |
| Создать или отредактировать по референсу  | `prompt` + `input_image`    | ID задачи `id` и `polling_url`  | `POST https://api.bfl.ai/v1/flux-2-pro` и другие |
| Получить итоговое изображение             | `polling_url`               | Подписанный URL `result.sample` | `GET {polling_url}`                              |

## Ключевые понятия

* **Размер задаётся через `width` / `height`**\: диапазон ширины и высоты FLUX 1.1 pro — 256–1440, и значения должны быть кратны 32. Это не уровень разрешения и не строка `size`.
* **Ultra использует `aspect_ratio`**\: у `/v1/flux-pro-1.1-ultra` нет полей ширины и высоты, вместо них используется `aspect_ratio` (по умолчанию `16:9`, в документации диапазон описан от `21:9` до `9:21`).
* **`seed` управляет воспроизводимостью**\: одинаковые промпт, параметры и `seed` используются для сравнения разных настроек; одинаковое изображение между моделями или версиями не гарантируется.
* **`steps` / `guidance` есть только у части моделей**\: FLUX.2 flex поддерживает `steps` (1–50) и `guidance` (1.5–10.0); у FLUX 1.1 pro этих полей нет.
* **Отправка и результат — два запроса**\: отправка возвращает `id`, `polling_url` и необязательный `cost`; после опроса до `Ready` изображение берётся из `result.sample`, во время обработки состояние — `Pending`, при ошибке или модерации контента возвращается соответствующее состояние.
* **Срок действия подписанного URL — около 10 минут**\: `result.sample` истекает быстро, файл нужно вовремя скачать и сохранить; не используйте этот адрес как долговременную публичную ссылку на изображение.

## Характеристики и возможности

| Эндпоинт                 | Управление размером                                                      | Референсное изображение                                  | Прочие основные поля                                                 | Формат ответа                        |
| ------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------ |
| `/v1/flux-pro-1.1`       | `width`, `height`\: 256–1440, кратны 32; по умолчанию 1024×768           | `image_prompt` (Base64, стилевой референс Flux Redux)    | `seed`, `prompt_upsampling`, `safety_tolerance` 0–6, `output_format` | После опроса берётся `result.sample` |
| `/v1/flux-pro-1.1-ultra` | Без `width` / `height`; используется `aspect_ratio`, по умолчанию `16:9` | `image_prompt`, `image_prompt_strength` 0.0–1.0          | `seed`, `prompt_upsampling`, `raw`, `safety_tolerance` 0–6           | То же                                |
| `/v1/flux-2-pro`         | `width`, `height`\: минимум 64, верхний предел в документации не указан  | `input_image` до `input_image_8`, максимум 8 изображений | `seed`, `safety_tolerance` 0–7, `output_format`                      | То же                                |
| `/v1/flux-2-flex`        | `width`, `height`\: минимум 64, верхний предел в документации не указан  | `input_image` до `input_image_8`, максимум 8 изображений | `steps` 1–50, `guidance` 1.5–10.0, `seed`, `output_format`           | То же                                |

Для `output_format` доступны `jpeg`, `png`, `webp`, по умолчанию `jpeg`. Для эндпоинтов, у которых в таблице не указан верхний предел, ориентируйтесь на OpenAPI schema соответствующего эндпоинта; не переносите ограничения ширины и высоты одного эндпоинта на другой.

## Процесс вызова

1. **Подготовьте ключ**\: создайте API Key в консоли BFL и используйте в заголовке запроса `x-key: $BFL_API_KEY`, а не `Authorization: Bearer`.
2. **Выберите эндпоинт**\: в зависимости от возможностей модели выберите `/v1/flux-pro-1.1`, `/v1/flux-pro-1.1-ultra` или другой эндпоинт `/v1/flux-*`.
3. **Отправьте задачу**\: отправьте JSON, задав `prompt`, поля размера, `output_format` и необязательный `seed`.
4. **Сохраните `polling_url`**\: прочитайте `id` и `polling_url` из ответа; не собирайте адрес опроса самостоятельно.
5. **Опрашивайте до `Ready`**\: используйте тот же `x-key` для запроса `polling_url`; при `Pending` продолжайте ожидание, при `Error` или состоянии модерации остановитесь и зафиксируйте причину.
6. **Скачайте и проверьте**\: скачайте `result.sample` до истечения подписанного URL, убедитесь, что файл открывается, проверьте размеры и содержимое, затем сверьте `cost` и журнал использования.

## Имитация вызова

Приведённые ниже сообщения являются примером, а не реальным ответом аккаунта; ID задач, URL и значения стоимости только иллюстрируют структуру.

Запрос отправки\:

```json
{
  "prompt": "一只小机器人在图书馆阅读，水彩插画，不要文字。",
  "width": 1024,
  "height": 768,
  "seed": 42,
  "output_format": "jpeg",
  "safety_tolerance": 2
}
```

Успешный ответ отправки (асинхронный, изображение ещё не создано)\:

```json
{
  "id": "task_example_01",
  "polling_url": "https://api.bfl.ai/v1/get_result?id=task_example_01",
  "cost": 0.04
}
```

Ответ завершения опроса (`status` равен `Ready`)\:

```json
{
  "id": "task_example_01",
  "status": "Ready",
  "progress": 1,
  "result": {
    "sample": "https://delivery.example.bfl.ai/sample/image.jpeg"
  }
}
```

Во время опроса также могут встречаться состояния `Pending`, `Error`, `Request Moderated`, `Content Moderated` и другие. Если модерация не пройдена, `result` может быть `null`, а причина указывается в `details`.

## Подключение и сеансы

* **Базовый URL**\: `https://api.bfl.ai`; также доступны `https://api.eu.bfl.ai` и `https://api.us.bfl.ai`. Опрашивайте тот же `polling_url`, который вернул ответ для выбранного входа.
* **Аутентификация**\: `x-key: $BFL_API_KEY`. Это наиболее заметное отличие от интерфейсов в стиле OpenAI\: не помещайте ключ в заголовок `Authorization`.
* **Полностью асинхронно**\: запрос отправки не возвращает изображение, только `id` и `polling_url`; чтобы получить результат, нужно отправить ещё один `GET`.
* **Отличия от OpenAI**\: нет эндпоинта `/v1/images/generations`, а также полей `size`, `quality`, `n`; размер управляется через `width` / `height` или `aspect_ratio`.
* **Обратный вызов вместо опроса**\: в запросе можно передать `webhook_url` и `webhook_secret`, и BFL вызовет webhook по завершении; при использовании обратного вызова всё равно проверяйте подпись и обрабатывайте события ошибок.
* **Вызов через шлюз сайта**\: замените адрес на `https://api.dwchainless.com` и используйте ключ сайта; FLUX — асинхронная задача, и то, передаёт ли шлюз `polling_url` и заголовок `x-key`, определяется каналом; если канал не подключён, используйте прямой официальный адрес выше.
* **Вызов через шлюз сайта**\: адрес запроса и способ аутентификации определяются описанием канала сайта; поля на этой странице относятся к нативному протоколу BFL, поэтому перед подключением к шлюзу проверьте доступность модели и объём передачи параметров.
* **Таймаут**\: запрос отправки должен возвращаться быстро; после таймаута сначала проверьте, не создана ли уже задача; интервал опроса рекомендуется около 0.5 секунды, а общее время ожидания задавайте с учётом модели и длины очереди, не повторяйте бесконечно.
