# Другие возможности и справочник по планируемым интеграциям

В этом разделе собраны интерфейсы, которые пока не открыты как универсальные возможности SimiRouter\: эмбеддинги, файлы, дообучение, Realtime, модерация и реранжирование. Их отличие от уже доступных возможностей не в сложности протокола, а в том, предоставляет ли шлюз маршрутизацию, аутентификацию и тарификацию.

## Обзор

Сначала посмотрите на статус, а затем решайте, стоит ли писать код. Нахождение в этом разделе не означает одинакового статуса.

| Статус                    | Значение                                                                        | Что можно сделать сейчас                                                                        |
| ------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Явно не поддерживается    | Шлюз не предоставляет эту возможность, и она не станет доступна от смены домена | Можно только обращаться к справочнику прямого подключения провайдера, используя ключ провайдера |
| Пока не поддерживается    | Сейчас не открыта, но сам протокол стабилен                                     | Проверяйте по справочнику прямого подключения провайдера, не оформляйте это как вызов шлюза     |
| Требуется проверка канала | Доступность зависит от аккаунта и конфигурации канала                           | Сначала уточните модель и маршрут, затем решайте, можно ли на это опираться                     |

## Ключевые понятия

* **Справочник прямого подключения**\: адреса и аутентификация в примерах этого раздела принадлежат провайдеру. Замена `api.openai.com` на домен шлюза не означает, что возможность доступна\: путь, сопоставление полей и права должны быть явно поддержаны каналом.
* **Принадлежность ключа**\: ключи провайдера и ключи SimiRouter не взаимозаменяемы. В примерах прямого подключения нужно использовать ключ соответствующего провайдера, нельзя подставлять туда ключ шлюза.
* **Принадлежность ресурса**\: ID файла, ID задачи и ID сеанса принадлежат проекту или организации, которые их создали; их нельзя напрямую переиспользовать между провайдерами и проектами.
* **Статус и тарификация**\: асинхронная задача сначала возвращает ID, затем нужно запрашивать статус; успешное создание не означает успешного выполнения, а отмена задачи не означает отмены уже понесённых расходов.

## Список возможностей

| Категория          | Статус SimiRouter                | Характер протокола                                                   | Справочник                             |
| ------------------ | -------------------------------- | -------------------------------------------------------------------- | -------------------------------------- |
| Эмбеддинги         | Пока не поддерживается           | Синхронный возврат векторов, отдельные пакетные задачи               | [Эмбеддинги](/simidoc/ru/apps/api/pending/embeddings)             |
| Управление файлами | Не поддерживается                | Загрузка, список, метаданные, скачивание и удаление                  | [Файлы](/simidoc/ru/apps/api/pending/files)                       |
| Дообучение         | Не поддерживается                | Создание асинхронной задачи обучения, статусы и события              | [Дообучение](/simidoc/ru/apps/api/pending/fine-tuning)            |
| Realtime           | Требуется выделенный канал       | Сеансы WebRTC / WebSocket с состоянием                               | [Realtime](/simidoc/ru/apps/api/pending/realtime)                 |
| Модерация          | Нужно проверить модель и маршрут | Синхронная классификация безопасности, а не гарантия фильтрации чата | [Модерация содержимого](/simidoc/ru/apps/api/pending/moderations) |
| Реранжирование     | Нужно проверить модель и маршрут | Синхронное ранжирование релевантности документов                     | [Реранжирование](/simidoc/ru/apps/api/pending/rerank)             |

Музыкальные интерфейсы описаны отдельно в разделе [Музыка (не поддерживается)](/simidoc/ru/apps/api/music). Сеансы реального времени, загрузка ресурсов и задачи обучения обычно требуют дополнительных прав, хранения и оплаты; перед интеграцией приложения нужно явно определить политику хранения и удаления данных.
