# Вызов инструментов

Вызов инструментов связывает модель с данными, вычислениями и внешними службами. Модель выбирает инструмент и формирует параметры; приложение или служба инструментов провайдера выполняет его. Результат инструмента и итоговый ответ на естественном языке — разные этапы.

## Обзор

| Возможность                | Кто выполняет  | Что вы видите                                                   | Типичный сценарий                                               |
| -------------------------- | -------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| Функция на стороне клиента | Ваша программа | Намерение вызова + результат выполнения, который вы возвращаете | Запрос к базе данных, вызов внутреннего API, списание со склада |
| Поиск на стороне сервера   | Провайдер      | Итоговый ответ и источники со ссылками                          | Поиск свежих данных, проверка фактов                            |

## Ключевые понятия

* **Определение инструмента**\: имя, описание назначения и JSON Schema параметров. Чем яснее описание, тем ниже вероятность, что модель выберет неверный инструмент или придумает параметры.
* **Намерение вызова**\: модель не выполняет код, а возвращает только `tool_calls`, где `arguments` — строка JSON. В потоковом ответе она может приходить фрагментами; собирайте её полностью перед разбором.
* **Выполнение и возврат**\: ваша программа проверяет параметры, выполняет функцию, затем отправляет результат сообщением с `role` равным `tool` и тем же `tool_call_id`; только тогда модель может продолжить.
* **Инструменты на стороне сервера**\: поиск выполняет провайдер, вы получаете только ответ и ссылки, не контролируя промежуточный процесс; не переносите на них схему работы клиентских функций.

## Имитация вызова

Запрос клиентской функции, ответ модели и возвращаемый результат выглядят так (содержимое условное)\:

```json
{
  "model": "gpt-5.5",
  "messages": [{ "role": "user", "content": "上海今天多少度？" }],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "查询指定城市的实时天气",
        "parameters": {
          "type": "object",
          "properties": { "city": { "type": "string" } },
          "required": ["city"]
        }
      }
    }
  ]
}
```

Модель возвращает намерение вызова, а не температуру\:

```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_abc",
            "type": "function",
            "function": {
              "name": "get_weather",
              "arguments": "{\"city\":\"上海\"}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ]
}
```

После выполнения функции добавьте результат новым сообщением и отправьте запрос снова\:

```json
{
  "role": "tool",
  "tool_call_id": "call_abc",
  "content": "{\"temp_c\": 18}"
}
```

Третий ответ — это итоговый ответ на естественном языке для пользователя. Во всей этой цепочке модель ни разу не обращалась к службе погоды; исполнителем является ваша программа.

### Поиск на стороне сервера

Инструмент на стороне сервера требует только одного круга\: вы объявляете инструмент, провайдер выполняет поиск, и один ответ содержит и запись о поиске, и итоговый ответ.

```json
{
  "model": "gpt-5.5",
  "input": "查找 OpenAI 官方文档中关于 Responses API 的说明，并提供来源链接。",
  "tools": [{ "type": "web_search" }],
  "stream": false
}
```

Возвращаемый `output[]` обычно сначала содержит действие поиска, затем итоговое сообщение со ссылками\:

```json
{
  "status": "completed",
  "output": [
    {
      "type": "web_search_call",
      "status": "completed",
      "action": { "type": "search", "query": "site:developers.openai.com Responses API" }
    },
    {
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "output_text",
          "text": "Responses API 用于生成模型响应……",
          "annotations": [
            {
              "type": "url_citation",
              "url": "https://developers.openai.com/api/docs/guides/text",
              "title": "OpenAI text generation"
            }
          ]
        }
      ]
    }
  ]
}
```

Ответ можно использовать, только если `status` равен `completed` и присутствует `message`; один `web_search_call` означает, что этап поиска завершён, но не что ответ полон. Ссылки берутся из `annotations[]`, их следует показывать как есть, не переписывая URL источников.

## Синхронность, поток и параллельность

* **Синхронно**\: один запрос возвращает полный вызов инструмента или итоговый ответ; для собственной функции обычно нужно выполнить её в приложении и отправить следующий запрос.
* **Поток**\: имя инструмента или параметры приходят фрагментами; разбирайте их после полной сборки параметров, нельзя выполнять неполный JSON.
* **Асинхронно**\: для длительного бизнес-инструмента приложение может создать фоновую задачу, но должно само обеспечить статус задачи и связь с результатом; объявление tools не создаёт асинхронную службу автоматически.
* **Параллельно**\: parallel\_tool\_calls позволяет модели предложить несколько вызовов функций за один тур; приложение должно параллельно выполнять только разрешённые и независимые операции. Это не увеличивает автоматически лимит частоты и не означает несколько HTTP-запросов.

## Границы безопасности

Зафиксируйте белый список инструментов, проверяйте типы и бизнес-рамки, разделяйте права чтения и записи. Для внешней отправки, оплаты, удаления и изменения прав необходимы подтверждение и идемпотентность. Вывод инструмента может содержать недоверенный текст; не используйте его как новые системные инструкции.
