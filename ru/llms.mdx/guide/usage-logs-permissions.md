# Права доступа к журналам использования и аудита

Это руководство объясняет видимость журналов использования и аудита по ролям, а также способ определить канал, который фактически обработал запрос.

## Журналы использования

### Суперадминистраторы

Суперадминистраторы могут просматривать полные журналы всех пользователей. Откройте [журнал использования](https://api.dwchainless.com/usage-logs/common) и выберите **Только ошибки** в фильтре типа, чтобы увидеть ошибочные вызовы всех пользователей. Фильтр сохраняет ошибки, возникшие во время повторных попыток, даже если итоговый запрос завершился успешно.

Столбец канала показывает канал, который фактически обработал запрос. При проверке маршрутизации используйте указанные в журнале канал, модель, статус и ID запроса, а не только название модели в клиенте.

### Администраторы

Администраторы могут просматривать только свои журналы запросов, пополнений, административных операций и ошибочных вызовов. Параметры имени пользователя, роли или URL не расширяют этот охват. Глобального фильтра **Только ошибки** у администраторов нет, но собственные ошибки видны согласно их правам.

### Обычные пользователи

Обычные пользователи могут просматривать только свои журналы запросов, пополнений и административных операций. Журналы ошибок и записи других пользователей им недоступны.

## Журналы аудита

Суперадминистраторы могут просматривать события аудита всех пользователей и фильтровать их по имени. Администраторы и обычные пользователи видят только события текущей аутентифицированной учетной записи; параметры страницы не расширяют серверные права.

## Обновление состояния канала

Событие аудита `channel.status_update` означает **обновление состояния канала**. Оно фиксирует ручную операцию над одним каналом. Текущий код принимает целевое состояние «включён» или «отключён вручную»; `changed=false` означает, что запрос выполнен успешно, но состояние канала не изменилось. Для пакетных операций используется `channel.status_update_batch`. Для уточнения операции проверьте детали события, оператора и время.

## Устранение неполадок

1. Подтвердите диапазон времени и ID запроса.
2. Для глобального поиска ошибок суперадминистратор должен выбрать **Только ошибки**.
3. Проверяйте фактические канал, модель и статус, а не только подпись клиента.
4. При тайм-ауте, ответе 5xx или прерванном потоке изучите журналы и ID запроса до повторной попытки, чтобы избежать двойного списания.
