画像生成

Images API でテキストから画像を生成し、返された Base64 結果を読み取ります。

API の説明

POST /v1/images/generations は prompt から1枚以上の画像を生成します。

接続先は https://api.dwchainless.com、リクエストヘッダーは Authorization: Bearer $API_KEY です。OpenAI への公式直接接続先は https://api.openai.com で、同じ Bearer 認証でも OpenAI のキーに置き換える必要があります。アクセス可能で目的の機能に対応するモデルを選択してください。

本ページは GPT Image のパラメータを使用します。互換画像モデルはサイズ、品質、応答形式が異なる場合があり、同一の公式標準として扱いません。

クイックスタート

  1. 設定を準備：API Key 管理でキーを作成し、モデルと料金から Images API 対応のモデル ID をコピーします。
  2. リクエストを送信：https://api.dwchainless.com/v1/images/generations に JSON を送信します。ヘッダーは Authorization: Bearer $API_KEY、本文には少なくとも model と prompt を含めます。
  3. 結果を読み取る：HTTP 2xx かつ data[] が空でない場合のみ成功です。GPT Image の data[].b64_json をデコードして保存します。
  4. 完了を確認：ファイルが開けることと必要なサイズを確認し、使用ログを照合します。

最小リクエストは次のとおりです。動作を確認したら、枚数、サイズ、ストリーミングを調整してください：

リクエストパラメータ

リクエスト本文は JSON。

フィールド型必須説明
modelstringはいImages API 対応の画像モデル ID。
promptstringはい被写体、構図、スタイル、文字を具体的に記述。
nintegerいいえ生成枚数。GPT Image ネイティブは1～10、例は1。
sizestringいいえOpenAI ネイティブは WIDTHxHEIGHT（幅・高さとも 16 の倍数、比率は 1:3〜3:1）または auto。SimiRouter は比率と resolution の組み合わせも受け付け、上限はモデル依存です。
resolutionstringいいえSimiRouter 拡張項目：比率と組み合わせる 1k、2k、4k の段階。ピクセル値ではなく、OpenAI ネイティブ API には存在しません。
aspect_ratiostringいいえSimiRouter 拡張項目：3:4 などの独立した比率。size に比率がある場合は size が優先。
qualitystringいいえauto、low、medium、high。一部新モデルは xhigh、max にも対応。
output_formatstringいいえpng、jpeg（例）、webp。公式スキーマには gif と svg もあり、モデルとプロジェクト権限が対応する場合のみ利用できます。
output_compressionintegerいいえJPEG/WebP 圧縮品質0～100。PNG には使用しません。
backgroundstringいいえauto、opaque、transparent。透明には対応モデルと PNG/WebP が必要。
moderationstringいいえauto、または対応する low。内容ポリシー通過を保証しません。
response_formatstringいいえ一部の互換モデルは url または b64_json を受理。GPT Image ネイティブでは使用しません。
streambooleanいいえtrue で画像 SSE。
partial_imagesintegerいいえstream=true で0～3枚の中間画像を要求。最終イベントを待つ必要があります。

GPT Image は Base64 を直接返すため、旧 response_format=url/b64_json に依存しないでください。一部の互換モデルではこの項目で URL か Base64 を選べますが、有効かどうかはモデルの説明と実際の応答に従います。旧 style=vivid/natural も使用せず、スタイルは prompt に記述します。

リクエスト例

サイズと形式

K は解像度の一般的な呼称で、ファイル容量や品質設定ではありません。実際の縦横サイズはモデルと縦横比に依存します。同じ縦横比で両辺を2倍にすると、総画素数は4倍になります。以下は用語の説明であり、全モデルで使用可能なサイズではありません。

OpenAI の size にはモデルが対応する 1024x1024 などの縦横サイズを指定します。1K という呼称は指定しません。quality と output_format は品質と形式を別々に制御します。

解像度の呼称一般的な画素数の例（モデルの対応を保証しません）
1K1024×1024 · 一辺が約千画素の水準
2K2048×2048 · 一辺が約二千画素の水準
4K4096×4096 / 3840×2160 · 一辺が約四千画素の水準

本サイトの画像単位の課金区分は別の規則です。この解像度の例をそのまま料金の基準にしないでください。 画像仕様と課金規則。

size の 3 つの書き方

一部の OpenAI 互換ゲートウェイは、明示ピクセルに加えて比率と解像度、または自動サイズも受け付けます。有効かどうかはモデルとゲートウェイに依存し、非対応の場合は明示ピクセルに戻してください。

書き方リクエスト断片説明
明示ピクセル（推奨）{"size":"1536x2048"}最も分かりやすく、プリセット換算の差を避けられます。
比率 + 解像度{"size":"3:4","resolution":"2k"}2K・3:4 のプリセットを使用。resolution は 1k、2k、4k のみ。
自動サイズ{"size":"auto"}モデルが縦横を選び、固定ピクセルは保証されません。
  • size に比率を書くと独立した aspect_ratio より優先され、明示ピクセルまたは auto は比率プリセットより優先されます。
  • 区分は resolution に書き、size=2k は送信しません。寸法の区切りには小文字の x を使います。
  • gpt-image-2 の任意サイズの公式上限は 3840×2160 です。4096×4096 などの大きな組み合わせは通常パラメータエラーになります。表の 4K は段階の目安で、そのピクセルサイズが必ず使えるわけではありません。
  • 14 のよく使う比率の 1K・2K・4K 早見表は画像仕様と課金規則を参照してください。

ストリーミング生成

対応モデルは stream=true とし、image_generation.partial_image で中間プレビュー、image_generation.completed で最終画像・用量を受信します。プレビューは最終結果ではなく、completed 前の切断は未完了です。汎用ポーリング用のタスク ID は返しません。

コード例

コード冒頭で API_URL と API_KEY を設定し。例では gpt-image-2 を使用します。API_URL は完全なリクエスト URL で、既定はゲートウェイ https://api.dwchainless.com です。例は標準ライブラリのみを使用し、1 回リクエストを送って返却 JSON を標準出力に表示します。画像の自動保存は行いません。

エージェント呼び出し Demo

ローカル実行と応答確認ができるエージェントに、以下のタスクをコピーしてください。まずこの形式の設定に従ってAPI_URL、API_KEY、MODEL を例に直接記入します。プロンプトにキーを記載しないでください。

エラーコード

HTTP ステータス意味または各社のエラー型対処
400無効なリクエスト必須項目、JSON、モデルパラメータ、文脈長を確認。
401認証失敗キーの存在、有効性、所属を確認。
403 / 404アクセス拒否／リソースなしモデル権限、リソース ID、URL を確認。
413リクエスト本文または画像が大きすぎる画像 URL を優先し、Base64 サイズや画像寸法を減らします。
429レートまたは割り当て制限応答本文でレート制限と残高不足を区別します。残高不足は再試行では解消しません。
500 / 502 / 503サービスエラー／上流の混雑／一時利用不可リクエスト識別子を保持し、一時障害のみ回数制限付きでバックオフ。

OpenAI のネイティブエラーには通常 error.message、error.type、error.param、error.code が含まれます。param、code は null の場合があり、常に存在することや HTTP 状態との一致は仮定しません。提供元到達前のエラーもあります。data が空、画像欠落、中間プレビューのみなら HTTP 200 だけで完了と宣言しません。

生成と編集は数十秒から数分かかる場合があります。クライアントのタイムアウトを十分に設定してください。要求の滞留は失敗とは限りません。タイムアウト、ストリーム切断、5xx の後は、再試行する前に要求が実行済みか確認し、重複生成や二重課金を避けます。内容ポリシーによる拒否（通常 400）では、そのまま再試行せずプロンプトや参照画像を修正してください。
