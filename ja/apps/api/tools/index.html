ツール呼び出し

独自関数やベンダー提供の検索を通じて、モデルを制御可能な外部機能に接続します。

ツール呼び出しは、モデルをデータ、計算、外部サービスに接続します。モデルはツールの選択とパラメータの組み立てを担当し、アプリまたはベンダーのツールサービスが実行を担当します。ツールの戻り値と最終的な自然言語の回答は異なる段階です。

概要

能力実行する主体目にする結果代表的なシーン
クライアント関数あなたのプログラム呼び出し意図 + あなたが返す実行結果データベース照会、内部 API 呼び出し、在庫引き当て
サーバー側検索ベンダー最終回答と引用元最新情報の検索、事実確認

中核となる概念

  • ツール定義：名前、用途の説明、パラメータの JSON Schema です。説明が明確なほど、モデルがツールを選び間違えたりパラメータを捏造したりする確率が低くなります。
  • 呼び出し意図：モデルはコードを実行せず、tool_calls のみを返し、その中の arguments は JSON 文字列です。ストリーミングレスポンスでは分割して届く場合があるため、すべて受信してから解析する必要があります。
  • 実行と返送：あなたのプログラムがパラメータを検証して関数を実行し、結果を role が tool で同じ tool_call_id を持つメッセージとして送り返すと、モデルは続行できます。
  • サーバー側ツール：検索はベンダーが行い、あなたは回答と引用だけを受け取ります。中間処理は制御できず、クライアント関数の使い方をそのまま当てはめることもできません。

呼び出しのシミュレーション

クライアント関数の 1 回のリクエスト、モデルのレスポンス、返送結果のフィールド形式は次のとおりです（内容はイメージです）。

モデルは気温ではなく呼び出し意図を返します。

関数を実行した後、結果を新しいメッセージとして追加し、再度リクエストします。

3 回目のレスポンスが、ユーザーに見せる自然言語の回答です。この一連の流れの中で、モデルは実際に天気サービスへアクセスしたわけではなく、あなたのプログラムが実行者です。

サーバー側検索

サーバー側ツールの往復は 1 回だけです。ツールを宣言すると、ベンダーが検索を実行し、1 つのレスポンスに検索記録と最終回答が同時に含まれます。

返却される output[] は通常、検索アクションが先に現れ、その後に引用付きの最終メッセージが続きます。

status が completed で message が存在する場合にのみ回答は利用できます。web_search_call だけが見える状態は検索段階が終わったことを示すもので、回答が完全であることを意味しません。引用は annotations[] から取得し、アプリは元の URL を書き換えずそのまま表示してください。

ツールの種類

ドキュメントリクエスト実行主体
関数呼び出しPOST /v1/chat/completions。Responses 形式もありますアプリが JSON Schema を定義し、パラメータを検証して独自の関数を実行します。
Web 検索POST /v1/responses + web_searchベンダーが検索を実行し、Web の出典と引用を返します。

同期、ストリーミング、並列

  • 同期：1 回のリクエストが完全なツール呼び出しまたは最終回答を返します。独自関数は通常、アプリが実行してから次のターンのリクエストを送る必要があります。
  • ストリーミング：ツール名やパラメータは断片として現れるため、パラメータをすべて受信してから解析する必要があり、途中の JSON を実行することはできません。
  • 非同期：時間のかかる業務ツールはアプリがバックグラウンドタスクとして構築できますが、タスク状態と結果の対応を自前で提供する必要があります。tools を宣言しても非同期サービスが自動的に作成されるわけではありません。
  • 並列：parallel_tool_calls はモデルが同じターンで複数の関数呼び出しを提案することを許可します。アプリは認可済みで相互に独立した操作のみを並列実行すべきです。レート制限のクォータが自動的に増えるわけでも、複数の HTTP リクエストを意味するわけでもありません。

セキュリティ境界

ツールのホワイトリストを固定し、型と業務範囲を検証し、読み取り権限と書き込み権限を分離します。外部送信、支払い、削除、権限変更などの副作用には確認と冪等制御を設けます。ツールの出力には信頼できないテキストが含まれる場合があり、それを新しいシステム指示として扱ってはいけません。
