# ファイルと内容認識

ファイル処理には、リソースを管理するアップロード API と、内容を読み回答を生成するモデル API の2層があります。生成リクエストへの添付は、再利用可能なファイル資源の保存とは異なります。

## 概要

| やりたいこと                 | 入力方式                              | ファイルの行き先       | 事前アップロードが必要か     |
| ---------------------- | --------------------------------- | -------------- | ---------------- |
| モデルに PDF を 1 部読ませる     | リクエストにインライン Base64 またはアクセス可能な URL | 今回のリクエスト内にのみ存在 | 不要               |
| 複数ターンのリクエストでファイルを再利用する | file\_id またはベンダーのファイル参照           | ベンダーのファイル資源    | 必要（公式 Files API） |
| バッチまたは超長ファイルの前処理       | アップロード後に処理完了を待つ                   | ベンダーのファイル資源    | 必要、かつライフサイクルがある  |

## 中核概念

* **インライン入力**：ファイルをリクエスト本文にエンコードしてメッセージとともに送信します。リクエストが終われば終了し、file\_id も後続の削除手順もありません。
* **ファイル資源**：先にアップロードして id を取得し、その後複数のリクエストで参照します。資源には帰属、有効期限、割り当てがあり、明示的に削除する必要があります。
* **ライフサイクル**：アップロード完了はテキスト抽出の完了でも、モデルがすでに理解したということでもありません。処理可能な状態になるまでポーリングしてから推論します。
* **サイズと形式**：制限はファイルサイズ、ページ数、長さごとに個別に設定されます。画像を圧縮してもファイル形式は変換されず、スキャン版 PDF には OCR 能力も必要です。
* **データ保持**：ファイル内容と認識結果の保持ポリシーはベンダーごとに異なります。機密資料は事前に権限と削除方法を確認してください。

## リクエストと機能

| 用途                                    | リクエスト                                         | 範囲                                         |
| ------------------------------------- | --------------------------------------------- | ------------------------------------------ |
| [PDF 内容認識](/simidoc/ja/apps/api/upload/file-recognition)        | POST /v1/responses + input\_file              | インライン Base64。Files API は不要。                |
| Chat の PDF 入力                         | POST /v1/chat/completions + type=file         | Chat の file オブジェクトを使用。Responses 構造ではありません。 |
| [Files API](/simidoc/ja/apps/api/pending/files)         | /v1/files                                     | ゲートウェイは未実装。公式のアップロード機能が当サイトでも使えるとは限りません。   |
| [Gemini メディア理解](/simidoc/ja/apps/api/chat/gemini-media) | POST /v1beta/models/\{model}\:generateContent | inlineData または利用可能な fileData。              |

## 呼び出し方式

インライン認識は同期 JSON またはテキストストリームで返り、いずれも1回のモデル要求です。一部公式アップロード・前処理での利用可能待ちは資源ライフサイクルであり、自動的なモデルのバックグラウンド実行ではありません。複数ファイルを1要求にまとめるか並列分割するかで、文脈、料金、合計容量の制限が異なります。

機密ファイルの送信前に処理権限とデータ方針を確認します。大文書は必要なページ・部分を選び、1回で終えるために無制限に入力を増やさないでください。出力の不確実性を保持し、金額、番号、法務・医療の結論は人が確認します。

## シミュレーション呼び出し

インライン認識は 1 回のリクエストで完了し、ファイルは Base64 で `input_file` に格納します。

```json
{
  "model": "gpt-5.5",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "总结这份合同的付款条款。" },
        { "type": "input_file", "filename": "contract.pdf", "file_data": "data:application/pdf;base64,JVBERi0xLjQK..." }
      ]
    }
  ]
}
```

レスポンスは通常のモデルメッセージで、認識結果は `output_text` にあります。

```json
{
  "status": "completed",
  "output": [
    {
      "type": "message",
      "content": [
        { "type": "output_text", "text": "（示意）合同约定分三期付款……" }
      ]
    }
  ]
}
```

このプロセス全体にアップロード手順も再利用可能な file\_id もありません。同じファイルについて再度質問するには、Base64 を再送信するか公式のファイル資源に切り替える必要があります。
