# 動画

動画には**生成**と**理解**があります。生成はテキストや参照素材から新しい動画を合成し、理解は既存の動画から要約、イベント、テキストの回答を抽出します。両者はリクエスト、所要時間、出力がまったく異なります。

## 概要

| 能力          | 入力               | 出力                  | 所要時間の目安  |
| ----------- | ---------------- | ------------------- | -------- |
| テキストから動画生成  | プロンプト            | 動画ファイルまたはダウンロード URL | 数十秒から数分  |
| 画像から動画生成    | 先頭フレーム画像 + プロンプト | 動画ファイル              | 数十秒から数分  |
| 先頭・末尾フレーム制御 | 先頭フレーム、末尾フレームの画像 | 両端が制御された動画          | 数分       |
| 動画理解        | 動画 + 質問          | テキストの要約または回答        | 動画の長さに依存 |

## 中核となる概念

* **解像度**：一般的な 480p、720p、1080p です。画面の鮮明さを決め、生成時間と価格にも直接影響します。下書きやプレビューは通常、より低い解像度しか対応しません。
* **アスペクト比**：`16:9` 横長、`9:16` 縦長、`1:1` 正方形です。比率と解像度が合わさって実際のピクセルが決まり、例えば 1080p の縦長は `1080x1920` です。
* **フレームレート（fps）**：1 秒あたりのフレーム数で、一般的には 24 または 30 です。フレームレートを上げるとファイルが大きくなり生成も遅くなりますが、動きが必ず自然になるわけではありません。
* **長さ**：1 本の動画の秒数で、モデルごとに上限があります。一部のモデルは長さの代わりにフレーム数に対応しており、同時に送信した場合の優先順位はインターフェースの説明で確認してください。
* **参照素材**：画像は先頭フレーム、末尾フレーム、スタイル参照に使用します。参照動画や音声の対応状況はモデルによる差が大きく、デフォルトで存在するとみなしてはいけません。
* **タスク状態**：作成時に返る ID は受理を意味するだけです。本当の成功は照会インターフェースの最終状態と有効な出力アドレスで判断し、`done` のような状態が常に成功を意味するとは限りません。

これらの仕様の利用可能な値と上限はモデルのバージョンで決まります。項目ごとに各サブページのリクエストパラメータ表を参照し、あるバージョンのフィールドを別のバージョンに当てはめないでください。

## リクエストの流れ

1. 作成リクエストはタスク ID を返します。これは受理を意味するだけで、動画が生成済みであることを意味しません。
2. 同じベンダー/チャネルのタスク照会インターフェースを使用します。数秒間隔を空け、全体の待機上限を設定し、失敗、期限切れ、キャンセルの場合は直ちに終了することを推奨します。
3. 成功の最終状態かつ有効な動画出力が存在する場合にのみダウンロードします。元のタスク ID、リクエスト ID、失敗理由を保存し、「HTTP 200」だけを記録しないようにしてください。
4. 結果の URL には有効期限があることが多いため、速やかに転送保存してください。ダウンロードリンクを永久ストレージのアドレスとして扱うことはできません。

動画生成は通常 SSE ではなく、ステータスのポーリングはリアルタイムの動画ストリームではありません。音声、解像度、長さ、先頭・末尾フレーム、複数参照の能力はモデルのバージョンごとに異なり、あるバージョンのフィールドをすべての動画モデルに当てはめることはできません。

## シミュレーション呼び出し

以下では Seedance プロトコルを例に、作成、受理、照会の 3 段階を示します。内容は例示であり、アドレスと認証は火山方舟の公式直接接続に属します。

作成リクエストではプロンプトと動画の仕様のみを送信します。

```json
{
  "model": "doubao-seedance-2-5-260628",
  "content": [
    { "type": "text", "text": "海边日落，镜头缓慢推进" }
  ],
  "resolution": "720p",
  "ratio": "16:9",
  "duration": 5
}
```

作成に成功してもタスク ID のみが返り、動画は返りません。

```json
{"id":"cgt-example"}
```

照会で最終状態に達し、結果のアドレスが存在する場合にのみ完了とみなします。

```json
{
  "id": "cgt-example",
  "status": "succeeded",
  "content": { "video_url": "https://example.com/video.mp4" },
  "error": null
}
```

状態が `queued` または `running` の場合は待機を続けます。`failed`、`expired`、`cancelled` の場合は直ちにポーリングを停止し、`error` を保存します。動画生成には SSE の増分がなく、結果はポーリングまたはコールバックでしか取得できません。

## ベンダーのアドレスと SimiRouter

各サブページは**ベンダーの公式プロトコル**に沿ってフィールドと流れを整理しています。例のリクエスト本文、パス、ステータス項目は、まずベンダーへ直接接続する際の参考として扱ってください。ゲートウェイのアドレス `https://api.dwchainless.com` と SimiRouter キーは、ページでゲートウェイへのマッピングが明示されている場合にだけ使用します。同名モデルが開放済みか、どのパスを通るか、フィールドをどうマッピングするかは、アカウントのモデル一覧と現在のチャネル設定を基準にしてください。ドメインだけを置き換えて、ベンダーのリクエストをゲートウェイへ送らないでください。

ベンダーのキー、火山の AK/SK、SimiRouter キーは相互に互換性がありません。チャネルに明確なマッピングがない場合は、ドメインを置き換えるだけで有料の生成を開始しないでください。
