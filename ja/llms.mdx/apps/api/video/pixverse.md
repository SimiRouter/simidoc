# PixVerse 動画

## 概要

PixVerse 公式 OpenAPI は通常の HTTP リクエストで非同期生成タスクを送信します。作成に成功すると `video_id` が返り、同じ ID で状態を照会して動画のアドレスを取得します。テキストから動画生成と画像から動画生成は別々の入口です。画像から動画生成では、先に画像をアップロードして `img_id` を取得してから送信します。

| やりたいこと      | 入力                                               | 出力              | エンドポイント                                   |
| ----------- | ------------------------------------------------ | --------------- | ----------------------------------------- |
| テキストから動画を生成 | プロンプト、長さ、`quality`、`aspect_ratio`                | `video_id`      | `POST /openapi/v2/video/text/generate`    |
| 画像から動画を生成   | アップロード済み画像の `img_id`（またはテンプレートの `img_ids`）とプロンプト | `video_id`      | `POST /openapi/v2/video/img/generate`     |
| タスク結果を照会    | `video_id`                                       | 状態、動画 URL、実際の仕様 | `GET /openapi/v2/video/result/{video_id}` |
| 画像をアップロード   | 画像ファイル                                           | `img_id`        | `POST /openapi/v2/image/upload`           |

## 中核となる概念

* **タスクのライフサイクル**：作成時に返る `ErrCode=0` と `video_id` は、タスクが受理されたことだけを示します。照会ステータスは `1` が完了、`5` が生成中、`7` がコンテンツ審査失敗、`8` が生成失敗で、`1`、`7`、`8` はいずれも終端状態です。
* **2 つの ID は用途が異なる**：`video_id` は業務タスクの識別子で、照会とダウンロードに使います。`Ai-trace-id` はリクエストごとに新しく生成する UUID で、追跡専用であり、冪等キーではありません。使い回すと別のタスクが作成される可能性があります。
* **ポーリングの間隔**：公式は 3〜5 秒ごとの照会を推奨しています。クライアントは全体の待機上限を設定してください。`7` または `8` になったら直ちに停止し、同じタスクを再試行し続けないでください。
* **課金単位**：作成レスポンスの `Resp.credits` は、このタスクで消費したクレジットです。実際の単価、プラン、返金規則はベンダーの価格ページとアカウントの請求に従います。
* **画角と長さは別々に制御する**：テキストから動画生成では `quality` で解像度区分を、`aspect_ratio` で画角を指定します。画像から動画生成には `aspect_ratio` フィールドがなく、画角は入力画像またはテンプレートで決まります。`duration` の有効値はモデルごとに変わるため、インターフェースの 1〜15 という範囲だけで記入してはいけません。

## 仕様と能力

| 指標     | 確認済みの値                                                                                    |
| ------ | ----------------------------------------------------------------------------------------- |
| モデル ID | `v6-max`、`c1`、`v6`、`v5.6`、`v5.5`、`v5`、`v5-fast`、`v4.5`、`v4`、`v3.5`。`v5-fast` にはアカウント権限が必要 |
| 解像度    | `quality`：`360p`、`540p`、`720p`、`1080p`                                                    |
| アスペクト比 | テキストから動画生成：`16:9`、`9:16`、`4:3`、`3:4`、`1:1`、`2:3`、`3:2`、`21:9`。画像から動画生成：このフィールドなし          |
| 長さ     | インターフェース範囲は 1〜15 秒。C1、V6 は 1〜15 秒、V5.5、V5.6 は 5、8、10 秒、旧モデルは 5 または 8 秒                    |
| 音声     | `generate_audio_switch` のブールスイッチで、既定は `false`。V5.5、V5.6、V6、C1 はネイティブ音声に対応                 |
| 参考画像   | 画像から動画生成では先にアップロードして `img_id` を取得。テンプレートタスクでは `img_ids` と `template_id` を組み合わせる           |
| 課金計量   | 作成レスポンスが `Resp.credits` を返す。単価はベンダーの価格ページに従う                                              |

選択時はまずモデルの世代を見てから、`quality` と `duration` を確認します。`quality` は出力ピクセルの区分だけを決め、画角は変えません。`aspect_ratio` は形状だけを決め、最終的なピクセルは両者で決まります。画像から動画生成には `aspect_ratio` フィールドがないため、テキストから動画生成のリクエスト本文をそのまま流用せず、画角は入力画像またはテンプレートで決めてください。作成レスポンスの `Resp.credits` は予算記録に適していますが、実際の課金と返金はアカウントの請求に従います。

## 呼び出しフロー

1. PixVerse 開放プラットフォームで API キーを作成します。リクエストには `API-KEY` ヘッダーを使用し、プロンプトやコードリポジトリに書き込まないでください。
2. 画像から動画生成では、先に `POST /openapi/v2/image/upload` を呼び出して画像をアップロードし、レスポンスの `Resp.img_id` を保存します。テキストから動画生成ではこの手順を省略します。
3. 対応する生成エンドポイントに JSON を送信します。必須フィールドは `model`、`prompt`、`duration`、`quality` で、テキストから動画生成ではさらに `aspect_ratio` が必要です。リクエストごとに新しい `Ai-trace-id` を生成します。
4. 作成レスポンスの `Resp.video_id` を保存します。`ErrCode=0` を動画が生成済みであると解釈しないでください。
5. 3〜5 秒ごとに照会エンドポイントを呼び出します。`status=1` かつ `Resp.url` にアクセスできる場合にのみダウンロードします。`status=7` では内容を修正してから再試行するか判断し、`status=8` では `Ai-trace-id` を調査用に保存します。
6. 動画を自分のストレージへ転送保存します。結果 URL のアクセス方針と有効期限はベンダーの説明に従い、永久に公開されるアドレスとして扱わないでください。

## シミュレーション呼び出し

以下のメッセージはフィールド構造の説明専用です。タスク ID、クレジット、URL はすべて例示値であり、実際のアカウントのデータではありません。

テキストから動画生成タスクを作成：

```json
{
  "model": "v6-max",
  "prompt": "示例：海边日落，一艘白色帆船缓慢驶过，镜头平稳。",
  "duration": 5,
  "quality": "720p",
  "aspect_ratio": "16:9",
  "seed": 20260804,
  "generate_audio_switch": false
}
```

作成に成功するとタスク ID と消費クレジットのみが返ります：

```json
{
  "ErrCode": 0,
  "ErrMsg": "Success",
  "Resp": {
    "video_id": 900000000000001,
    "credits": 12
  }
}
```

`status=1` になって初めてダウンロード可能なアドレスが得られます：

```json
{
  "ErrCode": 0,
  "ErrMsg": "Success",
  "Resp": {
    "id": 900000000000001,
    "status": 1,
    "url": "https://example.com/demo-pixverse.mp4",
    "duration": 5,
    "quality": "720p",
    "aspect_ratio": "16:9",
    "outputWidth": 1280,
    "outputHeight": 720,
    "has_audio": false,
    "credits": 12
  }
}
```

`status=5` ではポーリングを続けます。`status=7` または `status=8` では直ちに終了し、`ErrMsg`、`Error.Message`、`Ai-trace-id` から失敗理由を記録します。

## 接続とセッション

* **ベースアドレス**：`https://app-api.pixverse.ai`。生成と照会はすべて `/openapi/v2/` の下にあります。
* **認証ヘッダー**：`API-KEY: PASTE_API_KEY_HERE`、`Content-Type: application/json`。さらにリクエストごとに新しい `Ai-trace-id` を追加します。
* **2 組のアドレス**：直接接続では `https://app-api.pixverse.ai` を使い、認証ヘッダーは `API-KEY` です。`https://api.dwchainless.com` と `Authorization: Bearer` および当サイトのキーは、チャネルがこのゲートウェイへのマッピングを明示的に確認した場合だけ使用します。アドレスと認証を置き換えるだけでは不十分です。SimiRouter のチャネルがこれらのパスをマッピングするか、統一動画プロトコルに切り替えるかはチャネル設定次第です。ドメインを置き換えるだけでフィールド互換と仮定してはいけません。
* **タイムアウトと冪等性**：作成リクエストがタイムアウトしても、サーバーが受理していないとは限りません。保存済みの `video_id` で先に照会し、存在しないことを確認してから再試行してください。同じプロンプトを連続送信して「進捗を催促」しないでください。
* **エラー判定**：HTTP 200 でもゼロ以外の `ErrCode` が含まれる場合があります。業務エラーでは `ErrCode`、`ErrMsg`、および任意の `Error.Type`、`Error.Param` を読み、HTTP ステータスコードだけを見ないでください。
