# ファインチューニング（未対応）

モデルのファインチューニングは、学習データによって基礎モデルの動作を調整し、推論に使用できる新しいモデルを生成します。OpenAI は教師ありファインチューニング、直接選好最適化（DPO）、強化学習ファインチューニングなどの方法を提供しており、利用可能な方法は選択した基礎モデルによって異なります。

**SimiRouter は現在学習 API に未対応です。以下は OpenAI 公式説明と直接接続例で、プロジェクトのキーが必要です。学習は有料となる場合があります。**

OpenAI はセルフサービスのファインチューニングを段階的に終了しています。新規ユーザーは学習タスクを作成できず、対象となる既存ユーザーも、基礎モデルが先に終了しない限り **2027年1月6日** までしか作成できません。既存のファインチューニング済みモデルは、基礎モデルが非推奨になるまで推論に限って利用できます。対象条件、モデル、日付は変わる可能性があるため、利用前に[公式の非推奨スケジュール](https\://developers.openai.com/api/docs/deprecations)を確認してください。

## 概要

ファインチューニングが変えるのはモデルの重みであり、プロンプトではありません。安定した形式の制約、固定されたトーン、ドメイン固有の表現に適しています。頻繁に変わる知識の注入には適していません。そのような要件には検索やより長いシステムプロンプトを使う方がコストを抑えられます。効果の検証には、学習に参加していない独立したサンプルを必ず使用してください。

| やりたいこと      | 入力                  | 出力                            | 実行方式                  |
| ----------- | ------------------- | ----------------------------- | --------------------- |
| 専用モデルを学習する  | JSONL 学習セット + 基礎モデル | タスクオブジェクトと `fine_tuned_model` | バックグラウンドで非同期、状態をポーリング |
| 学習プロセスを観察する | タスク ID              | イベントログと指標                     | ページング照会。SSE ではありません   |
| 学習を停止する     | タスク ID              | キャンセル済みのタスクオブジェクト             | 同期リクエスト               |

## 中核となる概念

* **基礎モデル**：利用可能な方法と価格を決定します。基礎モデルによって対応する方法とパラメータが異なり、方法を間違えるとタスク作成時に拒否されます。
* **学習セットと検証セット**：JSONL で、各行が 1 つの会話サンプルです。公式の最低要件は 10 件で、通常は 50 件から始め、50〜100 件で明確な改善が見られることがよくあります。検証セットは別途用意し、学習セットと重複させてはいけません。
* **タスク状態**：`queued`、`running`、`succeeded`、`failed`、`cancelled` です。`succeeded` のみが推論可能な新しいモデルを生成します。`failed` の場合は `error` を読んで、データの問題かパラメータの問題かを判断します。
* **生成モデル**：成功後に `fine_tuned_model` 識別子が返され、これを使って基礎モデルの代わりに推論を開始します。モデルには独立したライフサイクルがあり、必要に応じて自分で削除します。
* **コスト**：学習は Token で課金され、生成モデルは保存期間中にストレージ費用が発生する場合があります。小さいサンプルで試してから拡大する方が、一度に全量データを送信するより制御しやすいです。

## 基本フロー

1. 選択したファインチューニング方法に従って JSONL 学習セットを準備し、検証セットを別途準備します。
2. [公式ファイルアップロードインターフェース](/simidoc/ja/apps/api/pending/files/upload)を通じて `purpose=fine-tune` でデータをアップロードします。
3. その方法に対応するモデルを選択し、タスクを作成してタスク ID を保存します。
4. タスクの状態とイベントを照会します。`succeeded` は成功、`failed` は `error` を読む必要があり、`cancelled` はキャンセル済みを意味します。
5. 学習成功後、返された `fine_tuned_model` を使用して推論し、独立した評価セットで効果を検証します。

作成リクエストの成功は学習の成功を意味せず、タスクのキャンセルも既に発生した利用量が取り消されることを意味しません。ネットワークのタイムアウトだけで同じ学習タスクを直接重複作成しないでください。
