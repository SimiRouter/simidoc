# Files API（未対応）

Files API は OpenAI のファイルリソース管理インターフェースです。アップロード後にファイル ID を取得し、ファインチューニング、バッチ処理、その他ファイル ID を受け付ける公式エンドポイントから参照できます。モデルによるファイル内容の認識能力とは異なります。

**SimiRouter は現在 Files API に未対応です。以下は OpenAI 公式説明・直接接続例で、OpenAI プロジェクトのキーが必要です。**

## 概要

Files API が解決するのは「1 回アップロードして何度も参照する」ことです。ファイルはまず独立したリソースとして存在し、その後ファインチューニングやバッチ処理などのエンドポイントが ID で取得します。学習セット、バッチリクエスト本文、繰り返し読み取る必要のある素材に適しています。単一の会話内の添付ファイルはこのインターフェースを使わず、リクエスト内で直接渡します。

| 利用シーン                    | アップロード時のマーク         | アップロード後に必要なこと         |
| ------------------------ | ------------------- | --------------------- |
| 教師ありファインチューニングの学習データ     | `purpose=fine-tune` | 学習タスクを作成し、状態をポーリングする  |
| バッチリクエストまたは出力            | `purpose=batch`     | バッチタスクを作成し、状態をポーリングする |
| その他ファイル ID を受け付けるエンドポイント | エンドポイントの要件に従う       | そのエンドポイントのドキュメントに従う   |

## 中核となる概念

* **ファイル ID とスコープ**：ID はそれを作成したプロジェクトまたは組織に属し、ベンダー間やプロジェクト間で再利用できません。別のサービスのファイル ID を OpenAI のリクエストに入れると 404 または 403 になります。
* **purpose が用途を決める**：アップロード時の `purpose` は、データが誰に使われるかを示します（`fine-tune`、`batch` など）。消費側のエンドポイントはさらにそれぞれ形式、サイズ、行数を検証します。
* **ライフサイクル**：アップロードの成功はリソースが存在することを示すだけです。学習やバッチ処理が完了したかどうかは、対応するタスクの状態を確認する必要があり、アップロード結果だけで判断することはできません。
* **内容とメタデータの分離**：ファイルオブジェクトの `filename`、`bytes`、`status` はメタデータです。モデルが見る内容は消費側のエンドポイントが読み取るものであり、両者は自動的に同期しません。

## インターフェースと実行方式

| 操作                           | 公式リクエスト                           | 実行方式                              |
| ---------------------------- | --------------------------------- | --------------------------------- |
| [ファイルのアップロード（未対応）](/simidoc/ja/apps/api/pending/files/upload) | `POST /v1/files`                  | multipart アップロード。ファイルオブジェクトを同期返却。 |
| [ファイル情報の取得（未対応）](/simidoc/ja/apps/api/pending/files/retrieve) | `GET /v1/files/{file_id}`         | メタデータを同期返却。                       |
| [ファイル一覧（未対応）](/simidoc/ja/apps/api/pending/files/list)        | `GET /v1/files`                   | 同期ページング照会。                        |
| [ファイル内容の取得（未対応）](/simidoc/ja/apps/api/pending/files/content)  | `GET /v1/files/{file_id}/content` | ファイルのバイトをダウンロード。モデルの SSE ではありません。 |
| [ファイル削除（未対応）](/simidoc/ja/apps/api/pending/files/delete)      | `DELETE /v1/files/{file_id}`      | リソースを削除し、削除結果を返します。               |

ファイルのアップロード成功は、その消費タスクの完了を意味しません。学習、バッチ処理、インデックスの処理状態はそれぞれのエンドポイントで照会します。ファイルの用途、形式、サイズ制限も消費側のエンドポイントが合わせて決定します。

## リソースとセキュリティ

ファイル ID はそれを作成したプロジェクトまたは組織に属し、別のベンダーやゲートウェイのファイル ID をそのまま OpenAI に使用することはできません。例では環境変数からキーを読み取ります。学習セット、個人情報、キーを公開リポジトリに書き込んではいけません。
