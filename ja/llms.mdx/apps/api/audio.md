# 音声

音声 API は、テキストを音声に変える、録音を文字にする、音声の内容を理解するために使用します。音声合成、音楽生成、動画の音声トラックは異なる能力であり、モデルとエンドポイントを混用しないでください。

## 概要

| やりたいこと               | 方向          | 代表的な出力            | 課金単位              |
| -------------------- | ----------- | ----------------- | ----------------- |
| テキストを読み上げる、ナレーションを作る | テキスト → 音声   | MP3、WAV などの音声ファイル | 入力文字数または音声の長さ     |
| 録音を文字にする             | 音声 → テキスト   | 元言語の文字、タイムスタンプ    | 音声の秒数または分数        |
| 外国語の録音を英語にする         | 音声 → 英語テキスト | 英語の文字、元言語は保持しない   | 音声の長さ             |
| 録音の内容を理解する           | 音声 → 分析テキスト | 要約、話者、結論          | 入力音声に対応する Token   |
| 人とリアルタイムに対話する        | 双方向の音声ストリーム | 連続した音声とイベント       | セッションの長さまたは Token |

## 中核となる概念

* **サンプリングレート**：1 秒あたりのサンプリング回数で、一般的な 16kHz（音声認識には十分）と 24kHz、44.1kHz（より高音質）があります。サンプリングレートが一致しないと、再生時の音程がずれたり、文字起こしの品質が低下したりします。
* **ビット深度とチャンネル**：16 bit モノラルは音声シーンで一般的な選択です。ステレオやより高いビット深度はファイル容量を増やしますが、モデルが活用するとは限りません。
* **コンテナとエンコード**：MP3 は非可逆で容量が小さく、WAV は通常無圧縮で容量が大きくなります。PCM はコンテナのない生のサンプリングデータで、再生時にはサンプリング仕様を手動で指定する必要があります。
* **長さとサイズ**：アップロード制限はファイルサイズと長さの両方で課されることが多く、高サンプリングレートに変換しても認識精度は上がらず、制限を超えやすくなるだけです。
* **同期とストリーミング**：TTS は音声バイトを返し、ASR は JSON を返します。ストリーミングは最初の文字や最初の区間の待ち時間を減らしますが、課金総量は変わりません。

仕様の数値（最大長さ、対応形式、サンプリングレートの範囲）はモデルによって決まります。項目ごとに各インターフェースページのリクエストパラメータ表を参照してください。

## インターフェースの説明

| 能力           | 入力 → 出力                | リクエスト方式                                            | ドキュメント                          |
| ------------ | ---------------------- | -------------------------------------------------- | ------------------------------- |
| 音声合成（TTS）    | テキスト → 音声              | 単発の HTTP。一部モデルは分割送信や SSE に対応                       | [テキスト読み上げ](/simidoc/ja/apps/api/audio/speech)            |
| 音声文字起こし（ASR） | 音声ファイル → 元言語の文字        | multipart アップロード。一部モデルは文字起こしの SSE に対応              | [音声文字起こし](/simidoc/ja/apps/api/audio/transcriptions)     |
| 音声翻訳         | 多言語の音声ファイル → 英語の文字     | multipart の単発リクエスト                                 | [音声翻訳](/simidoc/ja/apps/api/audio/translations)          |
| Gemini 音声合成  | テキスト → 単一話者/複数話者の音声    | ネイティブ Interactions、対応する旧モデルは別途 generateContent を使用 | [Gemini TTS](/simidoc/ja/apps/api/audio/gemini)          |
| Gemini 音声理解  | 録音 → 要約、文字起こし、分析テキスト   | ネイティブのマルチモーダルリクエスト                                 | [音声理解](/simidoc/ja/apps/api/audio/gemini-understanding)  |
| MiMo 音声      | テキスト/参照音声 → 音声、録音 → 文字 | 独立した互換ルートまたは公式 Chat Completions                    | [MiMo](/simidoc/ja/apps/api/audio/mimo-audio)            |
| リアルタイム音声     | 継続的な入力と出力              | WebRTC / 双方向 WebSocket                             | [Realtime](/simidoc/ja/apps/api/pending/realtime) |

## 同期、非同期、ストリーミングの違い

* **同期 HTTP**：1 つのリクエストが音声ファイルまたは完全な文字起こしを返し、タスク ID やポーリングの手順はありません。
* **HTTP ストリーミング**：同じレスポンスで音声または SSE イベントを逐次返します。双方向のリアルタイムセッションとは異なります。バイナリストリームに JSON パースを適用しないでください。
* **非同期タスク**：まずタスク ID を取得し、次に状態を照会します。動画生成は通常この方式ですが、通常の TTS/ASR はこの流れではありません。
* **Realtime**：セッションが接続を維持し、クライアントは音声を継続的に送信し、再生を中断し、イベントを処理できます。ファイルアップロードで代用することはできません。

## シミュレーション呼び出し

音声合成のリクエスト本文は JSON ですが、レスポンスは JSON ではなく音声バイトです。

```json
{
  "model": "gpt-4o-mini-tts",
  "voice": "alloy",
  "input": "欢迎使用 SimiRouter。",
  "response_format": "mp3"
}
```

返されるヘッダーでファイルの保存方法が決まり、本文はそのまま `.mp3` に書き込みます。

```text
HTTP/1.1 200 OK
Content-Type: audio/mpeg
Content-Length: 24576

<二进制音频数据>
```

文字起こしは multipart アップロードを使用し、JSON を返します。

```json
{"text":"欢迎使用 SimiRouter。"}
```

同じ「音声」カテゴリ内でも、合成はバイナリを返し、文字起こしは JSON を返すため、パーサーを混用することはできません。例のモデル `gpt-4o-mini-tts` はベンダーにより非推奨とされています。代替モデルと移行方法は[テキスト読み上げ](/simidoc/ja/apps/api/audio/speech)を参照してください。

## 利用の前提

OpenAI 互換ページでは SimiRouter のアドレスと SimiRouter キーを使用し、ベンダーのネイティブな参考例ではベンダーのアドレスと対応するキーを使用します。モデルが利用可能かどうかは、アカウントのモデル一覧とチャネルの権限で決まります。ベンダーのすべての能力がゲートウェイで提供済みとみなしてはいけません。録音をアップロードする前に必要な許可を取得してください。音声をクローンするには音声の使用権が必要で、合成音声であることを聴衆に開示してください。
