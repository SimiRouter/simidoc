# 使用ログと監査ログの権限

このガイドでは、使用ログと監査ログのロール別表示範囲、およびリクエストを実際に処理したチャネルの確認方法を説明します。

## 使用ログ

### スーパー管理者

スーパー管理者はすべてのユーザーの完全なログを確認できます。[使用ログ](https://api.dwchainless.com/usage-logs/common)を開き、種類フィルターで **エラーのみ** を選ぶと、すべてのユーザーのエラー呼び出しを表示できます。最終リクエストが成功していても、再試行中に発生したエラーはフィルターに残ります。

チャネル列は、リクエストを実際に処理したチャネルを示します。経路を調査するときは、クライアントに表示されたモデル名だけでなく、ログの実際のチャネル、モデル、状態、リクエスト ID を使ってください。

### 管理者

管理者が確認できるのは、自分のリクエスト、チャージ、管理操作、エラー呼び出しのログだけです。ユーザー名、ロール、URL パラメーターでこの範囲を広げることはできません。管理者には全体の **エラーのみ** フィルターはありませんが、自分のエラー記録は権限に従って表示されます。

### 一般ユーザー

一般ユーザーが確認できるのは、自分のリクエスト、チャージ、管理操作に関するログだけです。エラーログや他のユーザーのログは確認できません。

## 監査ログ

スーパー管理者はすべてのユーザーの監査イベントを確認し、ユーザー名で絞り込めます。管理者と一般ユーザーは、現在認証されているアカウント自身の監査イベントに限られます。ページパラメーターでサーバー側の権限範囲を広げることはできません。

## チャネル状態の更新

監査イベント `channel.status_update` は **チャネル状態の更新** を意味します。1つのチャネルに対する手動の状態操作を記録します。現在のコードで指定できる対象状態は有効または手動無効です。`changed=false` はリクエストが成功したものの、チャネル状態が変わらなかったことを示します。複数チャネルの操作には `channel.status_update_batch` が使われます。具体的な操作はイベント詳細、操作者、時刻を確認してください。

## トラブルシューティング

1. 期間とリクエスト ID を確認します。
2. 全体のエラーを調査する場合、スーパー管理者は **エラーのみ** を選択します。
3. クライアントの表示名だけで判断せず、実際のチャネル、モデル、状態を確認します。
4. タイムアウト、5xx 応答、ストリーム中断では、重複課金を避けるため再試行前に既存ログとリクエスト ID を確認します。
